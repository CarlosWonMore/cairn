# Cairn 控制台（预览页 / 工作台）

本文描述 `cairn ui` 的两种形态、真实命令与真实边界。命令与 `src/interfaces/cli/main.ts` 的 HELP 一致，接口与 `src/interfaces/console/server.ts` 的路由表一致。

先读这段边界：

- 控制台**只服务本机**：只绑 `127.0.0.1`，没有 `--host` 之类的放开开关。
- 浏览器只拿到令牌，不拿到数据库路径；页面不放任何外部资源（无 CDN、无 Web Font、无外链图片），断网可用。
- 建议是**建议**：规则层（确定性）与 AI 层（复核包 → 模型判断 → 写回）只填"建议"这一格，晋升、合并、遗忘仍然只走 `plan_hash + approval_id`。控制台能签发审批，但签发仍是"人重抄哈希前 8 位"这一步，没有一键免检路径。
- 静态导出**默认输出全部正文（含 sensitive 记忆）**，见第 3 节风险说明与 `--redact`。

---

## 1. 两种形态

| 形态 | 命令 | 数据来源 | 能做什么 |
| --- | --- | --- | --- |
| 工作台 | `cairn ui` | 回环 HTTP + `/api/*` | 浏览、检索、生成计划草稿、签发审批、应用计划、触发同步 |
| 预览页 | `cairn ui --export <文件>` | 单文件 HTML 内联模型 | 只浏览（含全文），可双击打开、可离线转发 |

两者共用同一套装配层与前端资源，差别只在传输方式与写入口：预览页的所有写控件被 `data-static` 关掉。

```bash
# 工作台（默认自动打开浏览器）
cairn ui

# 不自动开浏览器 / 指定端口 / 机器可读输出
cairn ui --no-open
cairn ui --port 8080
cairn ui --json          # 打印 {url, tokenUrl, port, host} 后继续运行

# 预览页
cairn ui --export ~/tmp/preview.html
cairn ui --export ~/tmp/preview.html --redact
```

`npm run cli -- ui` 等价于 `cairn ui`（见 `docs/cairn-usage.md` 第 1 节的运行方式提醒）。

## 2. 端口与会话令牌

- 默认端口 **7767**；被占用时自动退到系统分配端口，并在 stdout 打印实际地址（`--port 0` 直接要求系统分配）。
- 每次启动生成一次性令牌（32 字节随机，`crypto.randomBytes(32)` 十六进制）。启动时打印的是**带令牌的完整 URL**：

```
控制台已启动：http://127.0.0.1:7767/?t=9f2c…（64 位十六进制）
令牌随进程一次性有效；按 Ctrl+C 停止服务。
```

- 页面加载时把 `?t=` 取出转存到 `sessionStorage`，并立刻 `history.replaceState` 把地址栏里的令牌擦掉——令牌不会停留在地址栏、书签或截图里。
- 令牌随进程生命周期有效；进程退出即失效。没有"记住我"，也没有持久化令牌文件。

端口或令牌异常时的真实行为：

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `E_VALIDATION: --port 必须是 0-65535 的整数`（exit 2） | 端口参数非法 | 传整数或省略 |
| 7767 起不来但服务仍可用 | 端口被占用，已回退随机端口 | 看 stdout 打印的实际 URL |
| 页面 401 | 令牌缺失/被截断/来自旧进程 | 复制 stdout 里的完整 `tokenUrl` 重开 |
| 页面 403 | `Host` 不是回环，或 `Origin` 是别站 | 用 `127.0.0.1` 或 `localhost` 打开，不要用局域网 IP |

## 3. 预览页（静态导出）

```bash
cairn ui --export ~/tmp/preview.html
```

真实输出（stdout 是 JSON，stderr 是诊断）：

```json
{
  "written": "/home/you/tmp/preview-personal.html",
  "bytes": 561576,
  "counts": { "memories": 4, "archives": 51, "items": 533, "batches": 12, "plans": 0 },
  "redacted": false,
  "degradedItems": 0,
  "warnings": ["45 条 blocked 条目只能给出占位符与扫描类别：它们的原文在导入阶段已按安全策略丢弃，不在库中"]
}
```

```
[cairn] 产物含明文本地记忆（4 条记忆 / 533 条快照条目，561576 字节）：请勿外传；需要外发请加 --redact。
```

行为细节：

- **文件名自动追加 `-personal`**（已带后缀则不重复追加）：`preview.html` → `preview-personal.html`。这是"三层告知"的第 1 层。
- 文件头横幅是第 2 层（写明含明文与条数），stdout 提示是第 3 层。
- 路径中的 `C:\Users\<你>` 一律折叠为 `~`，产物不含本机绝对路径与用户目录结构。
- 单文件、零外链：`<link>`、`<script src>`、`<img src>`、`@import`、`url(http…)`、`<iframe>` 全部为零，样式与脚本内联。
- 预览页仍可切换视图（左侧导航或 `1`–`7`）：浏览是只读动作，不因为"静态"就把导航关掉；但地址栏不会变（`file://` 下改地址会抛异常，静态页也应当是一份可转发的快照）。待处理与同步两个视图在静态产物里显示降级说明，因为它们需要可写连接与实时计算。
- 体积超过 **8 MB** 时自动降级为"元数据 + 前 500 条正文"，被裁掉的条数写进文件头与 warnings。
- 内联模型 JSON 对 `<`、`>`、`U+2028/2029` 做转义：正文里出现 `</script>` 不会截断文档。

**`--redact` 是唯一的反向开关**：它同时掩码 sensitive 记忆的正文与 blocked 条目的占位标记。刻意不提供 `--include-blocked` 之类的单独开关——两个开关并存会产生"我打开了 A，以为也打开了 B"的组合歧义。

### 关于 blocked 条目：原文物理不可得

这是一个必须说清的事实，不是开关问题：

- 导入阶段，扫描器判定为秘密/注入的条目，其正文在入库前就被替换成占位符（`[blocked:<类别>]`）。原文从未写入数据库，只在原始来源文件里。
- 因此"导出含 blocked 正文"在当前数据模型下**无法实现**：库里没有那份内容。预览页会如实标注"原文未入库"，而不是显示空白让人以为内容为空。
- 想回看被拦下的原文，只能打开原始来源文件本身；扫描判定与拦截面见 `docs/cairn-security.md`。

## 4. 工作台能做什么

| 视图 | 内容 | 快捷键 |
| --- | --- | --- |
| 概览 | 计数卡（待处理、快照、计划、审批）、层级表 | `1` |
| 记忆 | 作用域/状态/类型过滤、检索、点开看正文/修订/证据 | `2` |
| 导入 | 一条导入一行：来源、次数、条目数、clean/blocked/已晋升/剩余、自动整理结果；顶上选已签发策略做自动整理 | `3`、`P` |
| 审批 | 计划与审批状态，签发与应用 | `4` |
| 同步 | 配置状态、缺项说明、手动触发 push/pull | `5` |

其他键：`/` 检索、`M` 摘要/全文、`T` 明暗主题、`?` 快捷键提示、`Esc` 关闭抽屉（无抽屉时取消焦点）。

**为什么只剩 5 个视图**：早先的「快照 / 批次 / 待处理」三个视图说的是同一件事的三个侧面，用户要在三个页面之间来回对号。现在合成一张导入表（`buildImportRows()`，一条**导入**一行），要逐条看就点开右侧抽屉。同源重导**不合并成一行**——合并会把"这次又导进来 N 条"这个数字抹掉，而用户常常正是要看它；历史几次进 `<details>` 默认折叠。

### 抽屉

- 右侧覆盖面板，**非模态**：`role="dialog"` + 标题走 `aria-label`，不声明 `aria-modal`——抽屉打开期间主导航仍可交互，如实声明，不向读屏虚报"外面不可交互"。
- 三个关闭入口（`Esc` / 点遮罩 / 「关闭」按钮）共用同一段 `close()`；关闭后焦点**还给打开它的那一行**，不是落回 body。
- 抽屉里能看条目正文、blocked 条目会标「原文未入库」（原文在导入阶段已物理丢弃，不是接口藏起来了）。
- 「按建议全部处理」**先摊开会发生什么**：动作分布（晋升/合并/都保留/跳过各几条）、以及「需人判断 N（不纳入）」。确认后才生成计划。`needs_human` 的条目永远不进批量——那一层判断本来就不该由一次点击代替。
- 导航浮在遮罩之上（`z-index: 60` > 遮罩的 50）：抽屉打开时主导航仍亮、仍可点，**一次点击**就完成"关抽屉 + 切视图"（`go()` 内置切视图先收抽屉），不用先点一下关抽屉、再点第二下切视图。点遮罩空白处仍然关闭抽屉。

### 自动整理与撤销

- 顶部下拉只列**已经签发**的策略；页面没有任何签发入口（配钥匙必须在 CLI 里做）。下拉会记住本次选择，重绘后不跳回"请选择"。
- 「只预演」勾上时只分档不写库，结果用 toast 报"自动 N / 需人 M，应用 0"。
- 真跑之后该行显示「策略 <id> · 写入 N」，并出现「按策略撤销」；撤销前弹确认，文案明确说**转墓碑而不是物理删除**。

- **摘要/全文**：`mode=brief` 由服务端裁切（每条约 240 字符），`mode=full` 给全文。HTTP 响应**默认掩码 sensitive 正文**，只有显式请求 `redact=0` 才给明文——这是与静态导出不同的风险面：一个在浏览器里随时可关，一个会被复制走。
- **URL 即状态**：`view / q / scope / status / kind / batch / plan / drawer / item / mode` 全部写进地址，刷新或把链接贴给自己都能复现同一屏（含打开的抽屉）。过滤变更用 `replaceState`（不污染后退栈），切视图用 `pushState`。令牌参数 `t=` 在进页面后被摘掉（存进 sessionStorage），**其余参数原样保留**。
- **审批**：页面上要手动重抄计划哈希前 8 位才能签发。签发写入审计 `issued_via_webui`（CLI 签发是 `issued_via_cli`），事后能分清谁在哪儿签的。
- **同步**：未配置 vault 时按钮 disabled 并说明缺哪一项；配置了才允许触发 `POST /api/sync/push|pull`。

## 4.1 批注与待处置队列（add-memory-annotations）

批注是**人对记忆的旁注**，不是记忆本体：写在 `<home>/console/annotations.json`（与 `ai-reviews.json` 同目录），**不建表、不参与云同步、不进入任何上行包**。删掉这个文件即回到纯只读控制台，记忆本身不受任何影响。

三条硬边界：

- 批注**从不修改记忆**：正文、状态、修订链、outbox 都不动；写入后记忆仍可被正常检索与注入。
- `pending_forget` **从不执行删除**：WebUI 只做标记，界面明确显示"仍为活动状态，尚未删除"。
- 写入前复用 `scanText`：意见命中秘密或注入规则即拒绝，不回显原文、不脱敏保存。

### 用法

| 入口 | 能做什么 |
| --- | --- |
| 记忆列表 | 逐条勾选 → 选处置类别 + 意见 → 「批量标记」；单条失败不中断，报告成功/失败条数 |
| 记忆详情 | 「写下意见」：类别下拉 + 文本域；下方列出该记忆已有的批注 |
| 「批注」视图 | 按状态（待处理/已处置/已忽略）与类别过滤；记忆修订后批注标「意见可能已过时」并灰显，但**不删** |
| `cairn forget --pending` | 先打印全部待删条目（id + 摘要 + 标注时间），再逐条遗忘并逐条报告 |
| `cairn forget --pending --dry-run` | 只打印清单，零写入 |
| MCP `memory_annotations_list` | Agent 拉取批注；**不返回记忆正文全文**，只给标识、类别、意见与短摘要 |
| MCP `memory_annotation_resolve` | Agent 回写 `resolved` / `ignored`，记录 `mcp:<agent>` 与时间；不碰记忆 |
| `cairn doctor` | 待办批注数进 `notes` 一行；**不进 problems、不改退出码** |

处置类别：`needs_edit`（需要修改）、`needs_merge`（需要合并）、`can_delete`（可以删除）、`uncertain`（存疑待查）、`no_action`（无需处理）、`pending_forget`（标记待删）。`no_action` 不计入 doctor 的待办数。

待删两段式的理由：墓碑是 sticky 的（其他设备推旧版本也救不回来），所以执行动作留在有完整上下文的终端；WebUI 误触的成本从"永久删除一条记忆"降为"多一条可随时取消的标记"。

批注是**本机私有**的：跨设备只同步处置结果（修订走 `memory_update`、遗忘走既有 tombstone 上行），不同步批注本身。

## 5. 双层建议与 AI 复核

建议分两层，**并列存在、互不覆盖**：

- **规则层**（确定性、可复算）：`S-BLOCKED` / `S-DUP-EXACT` / `S-DUP-NEAR` / `S-FRAGMENT` / `S-FRONTMATTER` / `S-NUMERIC-CONFLICT` / `S-CODE-HEAVY` / `S-CLEAN-DEFAULT`。每条结论都带 `basis` 数组（键、值、说明），页面上可展开逐项复核。判定顺序里"数值冲突"排在"近似重复"之前——否则"改了口径的那条"会被静默合并掉。
- **AI 层**（按需）：由复核包驱动，模型逐条判断后写回。

复核流程（三条通道共用同一实现与同一套校验，只差入口）：

```bash
# 1. 生成复核包（会把条目正文交给模型读取；同时报出条数与字符总量）
cairn review pack --out ~/tmp/pack.json

# 2. 交给当前 Agent 会话逐条判断，产出 { runId, items: [{itemId, action, reason}] }
#    action 取值：promote | merge | keep_both | skip | needs_human

# 3. 写回建议（任一条不合法即整批拒绝，不落半批）
cairn review submit --input ~/tmp/reviews.json

# 4. 查看已写回的建议
cairn review list --batch <batchId>
```

同样的动作在别处的入口：

- 工作台：`POST /api/reviews/pack`、`POST /api/reviews/import`、`GET /api/reviews`
- MCP：`memory_review`（`action: pack | submit | list`，仅在存在待整理批次时暴露）

写回只影响建议层。建议本身**不产生任何晋升**：采纳只是往计划草稿里加一条，真正的晋升要经过 `plan → approve → apply`。条目正文在写回后被改动时，旧建议标记 `stale` 并退出默认采纳。

## 6. 安全边界与明确不防御的东西

已经做到的：

- 只绑回环；`Host` 白名单只接受 `127.0.0.1:<port>` 与 `localhost:<port>`（防 DNS rebinding）。
- 一次性会话令牌，`timingSafeEqual` 比较；令牌可走 `X-Cairn-Token` 头或 `?t=`，页面交换后立即从地址栏移除。
- 跨站拦截：`Origin` 与 `Sec-Fetch-Site` 判定；判定顺序固定为 `Host → Sec-Fetch-Site → Origin → 令牌`，使"非回环 Host"不会被"令牌缺失"掩盖。
- 写操作只接受 `POST`；用 `GET` 打写端点一律 404（`cairn ui` 的 `GET /api/sync/push` → 404，不会顺手把数据推上去）。
- 响应头 `Cache-Control: no-store` + `Content-Security-Policy: default-src 'none'` + `X-Content-Type-Options: nosniff`。
- 请求日志只记方法、去掉 query 的路径与状态码，绝不记正文，令牌不进日志。
- 浏览路径使用独立的**只读连接**（`openStore({ readOnly: true })`）：仓储写守卫把任何误写拒为 `E_READONLY`，"只打开看一眼"在数据目录层面确实零写入。真实库冒烟见 `artifacts/console-smoke-<date>.json`（DB 字节级 sha256 前后一致、表行数零变化）。

明确**不**防御的（写在这里，免得被误当成安全产品）：

- 本机上以你的身份运行的进程：它能读 `~/.cairn/data/cairn.db`，就能读一切，控制台加多少锁都不改变这一点。
- 恶意浏览器扩展、已 root/管理员权限的进程、屏幕录制。
- 静态导出产物本身：它是**明文文件**。生成了就按明文对待——放进同步盘、发给别人、提交进仓库，都是你的选择，控制台不会帮你撤回。
- 前端不做的防护：没有 CSRF token（因为所有写操作都要令牌头，跨站脚本拿不到 `sessionStorage` 里的令牌），没有速率限制，没有多用户与权限体系。

## 7. 与 CLI / MCP 的职责划分

| 通道 | 场景 | 授权级别 |
| --- | --- | --- |
| CLI | 管理动作：初始化、导入、审批签发、导出、备份 | 本机用户（`user` 通道） |
| MCP | Agent 会话内的读写：检索、候选、复核建议 | `agent` 通道，受作用域约束 |
| 控制台 | 浏览与"在页面上把一条建议变成一次签发" | 本机回环 + 一次性令牌 |

三者共用同一应用服务（`AppService`），不各自实现记忆规则；控制台的写操作最终调用的仍是 CLI 用的那些方法。审批通道是唯一被参数化的地方（`approve(planId, { channel })`），通道只改变审计里"谁在哪儿签的"，不改变 TTL、一次性、哈希绑定。

## 8. 故障排查

| 现象 | 检查 |
| --- | --- |
| 启动即报 `数据目录尚未初始化` | 先 `cairn init`；确认 `--home`/`CAIRN_HOME` 指向同一目录 |
| 页面白屏 | 打开控制台看报错；确认服务在跑、地址带令牌；`?` 键可看快捷键是否符合预期 |
| 页面一直"加载中…" | 令牌可能来自上一个进程（已失效），用最新 stdout 的 URL |
| 导出文件名没有 `-personal` | 只有 `ui --export` 路径会规范化；直接调 API 时由调用方负责 |
| 导出提示"已降级" | 产物超 8 MB，正文被裁到前 500 条；`--redact` 会显著减小体积 |
| 待处理为空但确有导入批次 | 没有 clean 条目、或该批条目已全部晋升；看导入表该行的「剩余」 |
| 审批按钮点了没反应 | 哈希前 8 位没抄对（大小写不敏感，长度必须够） |
| 抽屉打开后整页点不动 | 抽屉是整页遮罩，先 `Esc`；若切视图后仍被挡，是 `go()` 里没关抽屉（见 `test:ui` 的对应断言） |
| 分享出去的链接打开回到概览 | 页面摘令牌参数时把整段 query 清了（只能删 `t`，其余原样保留） |

## 9. 浏览器点击级验收

`npm run test:ui`（`scripts/e2e-console-ui.mjs`）用真实浏览器把界面点一遍。它补的是 `tests/console/*` 够不到的那层：源码断言只能证明"字符串写对了"，证明不了"点下去真打开了抽屉、`Esc` 真关了、焦点真回到了那一行"。

- 浏览器用**系统已装的 Chrome**（`channel: 'chrome'`），不下载 Chromium。
- 依赖是一次性的、**故意不写进 `package.json`**：缺 playwright 时脚本 exit 2 并打印 `npm i --no-save --no-package-lock playwright`，不静默跳过——静默跳过会让"UI 已验证"变成假象。
- 全程在临时 HOME 里造数据（`init` → 同路径导两次 → 签发策略），跑完自删；`CAIRN_KEEP_E2E=1` 可保留样本。
- 覆盖：导航替换、同源折叠的可见性、抽屉三入口与焦点归还、地址往返还原、批量面板先摊开再确认、自动整理预演/真跑/撤销确认、批注点选/批量/陈旧灰显/待删 dry-run、静态预览页无写入口、全程零脚本错误。
- 报告落 `artifacts/console-ui-<date>.json`（不入库）。2026-10-30 实测 46/46。

它抓到的三个缺陷（已修，并在 `tests/console/assets.test.ts` 留了形状断言）：

| 缺陷 | 症状 | 根因 |
| --- | --- | --- |
| 摘令牌时清掉整个 query | 分享链接打开永远回概览，抽屉打不开 | `replaceState(null,'',location.pathname)` 把 `view`/`drawer` 一起抹了 |
| 切视图不关抽屉 | 批量确认跳审批后整页点不动 | 遮罩盖在导航上，`go()` 没有 `closeDrawer()` |
| 策略下拉不记选择 | 预演完直接点真跑，只得到"先选一个策略" | 重绘重建了 `select`，选中值没存进 state |

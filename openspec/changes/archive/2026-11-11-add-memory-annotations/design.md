# Design: 记忆批注与待处置队列

## 上下文

用户诉求（2026-11-10）："作为我人类管理记忆的一个切入口，我希望可以批量管理记忆，通过 WebUI"。

关键约束来自 Cairn 的既有设计：

1. **记忆正文不可变**——改动走修订链追加，历史永不覆写。所以"批注"不能是"草稿版的正文"。
2. **墓碑是 sticky 的**——`forget` 之后其他设备推旧版本也救不回来。所以"点一下删除"太危险。
3. **同步只同步确定事实**——批注是人的思考草稿，同步它只会制造跨设备冲突。

## 决策

### D1：批注存 JSON 文件，不建表

**选择**：`~/.cairn/console/annotations.json`，与既有的 `ai-reviews.json` 同一模式。

理由：

- 批注是**派生数据**——删了不影响任何记忆；放库里会让它占 schema、参与迁移、还要被同步协议考虑；
- 现有 `review-store.ts` 已经证明了"JSON + 原子替换"这套足够可靠；
- 用户的明确选择是"不同步"，而放进 `memory` 相关表会天然被 outbox 逻辑覆盖到，反而要额外写排除逻辑。

代价要说清：JSON 文件**不能按内容检索**（只能按状态/类别过滤后线性扫）。当前规模（几十到几百条批注）无影响；若将来上万条应改表。

### D2：批注绑定「当前状态」而非「具体修订」

**选择**：批注记录 `memoryId` + 写入时的 `revisionId` 作为**快照证据**，但语义上只管"这条记忆现在该怎样"。

理由：用户选择 Q9-A。若绑定具体修订，记忆改过之后批注会指向历史版本，用户看到"这条被标了要改"却找不到对应内容——反而困惑。

**必须处理陈旧**：批注写入后记忆若被修改，批注应被标记为 `stale`（对比 `revisionId`），界面上灰显并提示"记忆已变更，意见可能已过时"。这与 `review-store.ts` 的 `staleReason` 是同一套做法，复用思路不重写。

### D3：待删走「标记 → 终端确认」两段式

**选择**：WebUI 只能写 `disposition: 'pending_forget'`，真正删除必须 `cairn forget --pending`。

理由：用户认可折中方案。技术上：

- 墓碑不可逆 → 执行动作放在有完整上下文的终端更安全；
- 终端能一次性打印全部待删清单，让用户在**看得到全貌**的情况下确认；
- WebUI 的误触成本从"永久删除一条记忆"降为"多一条待删标记"，而后者可以随时取消。

实现要点：`cairn forget --pending` MUST 先打印清单再执行，且 MUST 逐条报告结果；不能静默批量删。

### D4：MCP 工具只读 + 状态回写，不碰记忆

**选择**：`memory_annotations_list`（读）与 `memory_annotation_resolve`（回写状态）。

理由：用户选择 Q8-A。Agent 的职责是"看到意见 → 决定怎么改 → 用既有的 `memory_update` / `memory_forget` 去做"。批注接口不该有修改记忆的能力——那会让权限边界变模糊（批注是低风险操作，改记忆是高风险操作，不能共用一个口）。

返回值**不含记忆正文全文**，只给标识、类别、意见、以及能定位的摘要。原因：Agent 要改正文时应该用 `memory_get` 明确取一次（可审计、有痕迹），而不是从列表里顺走。

### D5：秘密扫描复用现有实现

批注的 `note` 是自由文本，用户可能贴进整段含密钥的内容。写入前 MUST 走 `scanText`，命中即拒绝。

**不做"脱敏后保存"**——那会让人误以为系统记住了完整内容。拒绝更诚实。

## 威胁模型

| 威胁 | 后果 | 缓解 |
|---|---|---|
| 用户把批注当"已执行" | 以为记忆已改，实际没动 | 界面在待删项上明确标注"仍为活动状态"；批注列表与记忆状态分开展示 |
| 批注泄漏秘密 | 秘密落盘到 JSON | 写入前 `scanText` 拒绝；不脱敏保存 |
| 批注文件被云同步带走 | 违背"批注不上云" | 文件在 `console/` 目录，与 `ai-reviews.json` 同级；同步只走 outbox 事件，从不扫该目录 |
| 陈旧批注误导用户 | 按过期意见改了记忆 | 对比 `revisionId` 标 `stale` 并灰显 |
| 批量标记把不存在的 id 也算成功 | 数字虚高 | 逐条校验、分别计数、如实报告 |

## 迁移与回滚

- 无数据库迁移。
- 回滚：删除 `annotations.json` 即完全回到纯只读控制台。

## 可观测性

| 观察点 | 位置 |
|---|---|
| 待办批注数 | 控制台首页、`cairn doctor`（作为 notes 一行，不进 problems） |
| 陈旧批注数 | 控制台批注列表顶部 |
| Agent 处置痕迹 | 批注的 `resolvedBy` / `resolvedAt` 字段 |

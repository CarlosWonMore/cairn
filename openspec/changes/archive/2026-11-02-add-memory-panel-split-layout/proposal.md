# Proposal: 记忆面板改为左右两栏

## Why

当前记忆面板（会话里的「记忆」tab）是**单列纵向堆叠**：状态 → 指标 → 本轮注入 → 活动记录。三个后果：

- **活动记录是看的最多的一块，却被压在最下面**，还要先滚过上面两段才能看到；宽屏上左右两侧大片留白，信息密度浪费。
- 活动记录顶部的筛选条里塞了「15 条 / 30 条 / 120 条」三个 chip——用户明确要求**不做条目数展示**，用滚动条代替翻页式取舍。
- 面板内部只有外层一个滚动条，状态区和活动记录共用同一个滚动容器，翻记录时状态会被滚走。

## What Changes

改成**左右两栏、各自滚动**：

| 位置 | 内容 |
|---|---|
| 左上 | 状态（● 已注入 / 未命中 / 已过滤）+ 召回条数、命中通道、预算占用、被过滤（保留，供诊断） |
| 左下 | 本轮注入的记忆（id / kind / 摘要），无内容时给占位文案 |
| 右侧 | 活动记录：顶部筛选条（自动召回 / 工具调用 / 简要 / 详细 / 文字 / 记录存储）+ 可滚动列表 |

- **自适应宽度与换行**：两栏用 `flex: 1 1 <基准宽度>` + `flex-wrap`，窄窗口自动上下堆叠，不做媒体查询（客户端插件只有内联样式，没有样式表注入通道）。
- **筛选条自适应**：chip 容器 `flex-wrap`，窄宽度换行而不横向溢出。
- **列表参考「轨迹」tab 的排版**：等宽数字时间戳、类型标签、摘要三段，行间细分隔线，正文 `overflow-wrap: anywhere`；滚动区 `flex:1 + min-height:0 + overflow:auto`。
- **移除条目数 chip**（15 / 30 / 120）；取数上限保留在本地配置里（默认 30），只是不再暴露开关。

### 不改什么

- **不改 Host→Client 的数据契约**：`/plugins/cairn-dsh-memory/usage` 的字段一个不加、一个不改。
- 不改召回、过滤、预算、摘要逻辑；不改 `cairn ui` 控制台（那是事后视图）。
- 不引入 UI 依赖或样式表，继续用 React.createElement + 内联样式。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-interfaces`：面板 MUST 在同一视图内分左右两栏并各自滚动，MUST NOT 要求用户先滚过状态区才能看活动记录；MUST 自适应宽度，窄宽度下 MUST 上下堆叠而不是横向溢出；MUST NOT 提供条目数量选择。

## Impact

- 修改：`plugin/dsh/src/client.js`（唯一实现文件，纯展示层）。
- 测试：`node --check plugin/dsh/src/client.js`（语法）；布局本身**无法在 CI 断言**（宿主 slot 内的真实 DOM 才能验证），按 `add-memory-usage-panel` 的先例如实标注为手工冒烟项。
- 风险：
  - **宿主容器若没有确定高度**，`height:100%` + 内部滚动会退化成一整块滚动 → 兜底用 `min-height:0` 且外层 `overflow:hidden`，最坏情况仍可整体滚动。
  - **hook 顺序**：所有 hook 必须仍在 `if (!data) return` 之前（Round-10 曾因此把面板渲染成空白）。
  - 视觉调整无自动化回归 → 改动限定在布局容器，数据与文案不动。

## 增量（2026-11-02 追加）：栏宽可拖拽

用户追加要求：左栏宽度可拖拽调整、布局能保存、也能恢复默认。

- **拖拽**：两栏之间加一个 8px 手柄（`cursor: col-resize`，`role="separator"`），pointer capture 拖动，占比限制在 25%–75%——任何一侧都不许吃掉整屏。
- **保存**：松手时把「左栏占比」写进 `localStorage`（`cairn-memory-tab-layout`）。存**占比**不存像素：换窗口大小后像素值会失真。不做「保存」按钮，与既有筛选器一致的自动持久化。
- **恢复默认**：右栏底部「重置布局」清掉该键，回到 flex 自适应（宽了并排、窄了堆叠）。
- **不改**：没拖过的用户完全走原来的自适应路径，行为与本次变更之前一致。

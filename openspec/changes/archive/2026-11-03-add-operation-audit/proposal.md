# Proposal: add-operation-audit

## Why

用户在 DSH 记忆面板验收（2026-11-02，Round-9）中明确要求：**凡是经 Cairn 记忆做的操作都要留痕留记录**，且展示可配置（筛选、程度、时长），对齐「轨迹」的持久度。

现状缺口（已验证，代码与提交 `3ba66e2` 可查）：

1. **检索操作零留痕**：`audit_event` 表（design D10）只记治理操作——计划、审批、配置备份、作用域排除、恢复与错误类别。`memory_search`/`memory_get` 等读取操作不留任何记录。
2. **留痕不可跨宿主、不可跨重启**：DSH 插件的活动记录是内存环（120 条，重启即清空）。ZCode / WorkBuddy 宿主完全没有操作史可查。
3. 轨迹（DSH 会话事件流）虽持久落盘，但它是宿主私有数据，不随 Cairn 主权层走，也无法在其他宿主查询。

留痕的权威位置应是核心审计层：三个宿主共享同一份本地操作史，保留期统一受控。

## What Changes

1. **服务层操作审计**：MCP server 处理的每一条记忆操作写一条摘要审计事件（新类目 `operation`）——action 为工具名，detail 仅含摘要计数（候选数、命中通道、耗时、结果状态、受影响对象 id）。**查询文本、调用参数、返回内容、记忆正文一律不入审计**。
2. **保留期（时长可配）**：`operation` 类目按可配置天数保留（默认 30 天），到期由维护路径清理；治理类目（计划/审批等）**永不自动清理**——审计完整性优先于存储。
3. **只读查询工具**：新增 MCP 工具 `memory_audit`，按类目/动作/起始时间/条数过滤，仅返回摘要字段；同形 CLI 子命令 `cairn audit list` 供独立验收。
4. **DSH 面板接入持久层**：记忆 tab 活动区改为「实时环（会话内）+ `memory_audit` 历史（跨重启）」合并展示；现有筛选器（类型/程度/条数）沿用，新增时间窗过滤。
5. **总开关**：`audit.operations=false` 可整体停写操作审计（治理审计不受此开关影响）。

## Capabilities

### 新增

- `operation-audit`：记忆操作摘要留痕、保留期治理、只读查询。全新能力，横切服务层，不修改既有能力的需求。

### 修改

（无——`memory-governance`、`scoped-retrieval`、`memory-store`、`local-console` 的既有需求不受影响；审计写入是服务层横切行为。）

## 非目标

- 不记录任何查询原文、调用参数、返回内容或记忆正文——面板与审计都只见摘要。
- 不做审计事件的上行或云同步：审计是本地主权数据。
- 不改治理审计的写入语义（不可变、不删改）。
- 不做跨设备审计合并或对账。
- 不新增宿主设置表单：展示配置由面板筛选器承担，保留期走 Cairn 配置（CLI/配置文件）。
- 不把操作审计接入召回或推荐逻辑。

## Risk

| 风险 | 评估与缓解 |
|---|---|
| 高频 search 的写放大 | 本地 SQLite 单条 INSERT 为微秒级；任务中用基准数字验证（≥1000 次/秒写入无退化）；兜底 `audit.operations=false` 一键停写 |
| 审计写失败影响主操作 | FAIL-OPEN：审计写入异常只记 stderr，绝不阻断记忆操作本身（对齐「维护退出会话关键路径」边界） |
| 保留期清理误删治理审计 | 清理 SQL 按类目白名单显式排除治理类目；测试锁定「治理条目在保留期后仍在」 |
| 审计表膨胀 | 保留期 + 清理即答案；任务含清理后行数断言 |

## 回滚

1. 运行时回滚：`audit.operations=false` 停写操作审计，治理审计与历史数据不受影响。
2. 代码回滚：`git revert`；schema 增量为追加式（新类目零迁移，或仅加索引），旧版本代码读新库不受影响。
3. 数据回滚：操作审计条目可按类目安全删除（`DELETE FROM audit_event WHERE category='operation'`），不触碰治理数据。

## 事实与假设的区分

| 类别 | 内容 |
|---|---|
| 已验证事实 | `audit_event` 表结构与治理类目现状（`src/store/audit.ts`）；MCP 工具面无审计查询工具（`src/interfaces/mcp/server.ts`）；DSH 插件活动环为内存态（提交 `3ba66e2`）；真实库 `audit_event` 在用 |
| 产品假设 | 用户需要的是「摘要级操作史」而非全文参数日志（Round-9 对话中用户以轨迹为参照，且秘密纪律不允许全文） |
| 待验证 | 写放大基准（任务清单首项）；`memory_audit` 工具名不与既有工具冲突（已核对 `server.ts` 工具清单，无冲突） |
| 外部条件 | 无阻塞项——纯本地能力，不依赖云端或宿主授权 |

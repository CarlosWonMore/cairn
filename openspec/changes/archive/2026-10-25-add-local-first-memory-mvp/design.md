# Design

## Context

本变更把 M0 的独立探针整合为本地 MVP。当前没有既有生产代码或用户数据需要兼容；`artifacts/m0/` 是可复跑证据，不是直接复制即合格的产品实现。

已确认的原型证据：

- Windows x64、Node.js 22.22.2 上，`node:sqlite` 支持 FTS5、trigram、备份和多进程写入；存储批报告 45 项通过、0 失败，中文 18 查询中 hybrid 与 LIKE 回退均达到该合成集的完整命中。
- 官方 MCP SDK 1.32.2 协议批经独立复跑，两轮均为 25/25 通过；stdio、初始化、工具调用、取消、超时和断开已有可复用合同。
- Agent 适配批在合成 HOME 中有 64 项测试；仅 Copilot CLI 做过隔离的真实 CLI 操作，其余宿主仍受 fixture-only 或公开接口边界约束。
- 初始化合同已有 22 项探针，覆盖发现不读正文、重复导入、伪造审批、计划篡改和精确卸载。
- 真实 ECS/OBS、macOS/Linux、全宿主认证均没有完成，不能进入本变更的已完成结论。

硬约束见 `openspec/config.yaml`。本变更不连接真实云端，不读取真实个人记忆，不修改真实 Agent 配置；本地模型明确排除。

## Goals / Non-Goals

**Goals:**

- 形成一个无模型、无网络也可使用的本地权威核心，以及 CLI/MCP 两类一致入口。
- 用同一作用域策略连接记录、检索、投影、导出和本地 outbox。
- 用确定性计划与审批连接当前 Agent 的语义整理能力，而不把授权判断交给模型。
- 让首次发现、导入、配置、原生入口和卸载都可独立执行、独立回滚。
- 将 M0 的故障注入与合同测试转成可重复的项目测试。

**Non-Goals:**

- 不实现 ECS/OBS 客户端、远端 relay、云端密钥托管或跨设备实际同步。
- 不实现本地模型、自动后台模型路由、向量数据库或图数据库。
- 不实现团队空间、共享权限、桌面 Pro、托管服务或公开 npm 发布。
- 不对所有宿主做私有存储适配，不实际关闭宿主原生自动记忆。
- 不在本次直接合并 M0 原型目录；按规格重建必要模块并迁移测试资产。

## Decisions

### D1：独立 TypeScript ESM 轻核心

采用 Node.js 22+、TypeScript ESM、npm 包与 `npx` 入口。按 `core / store / retrieval / governance / onboarding / interfaces / projection / jobs` 分模块，CLI 与 MCP 共用应用服务，禁止各自实现一套记忆规则。

备选是 Python + uvx 或直接 fork Engram/agentmemory。不采用的原因分别是团队目标分发为 npm/npx，以及现有项目在运行时、常驻服务或核心语言上会引入不必要绑定。M0 源码只吸收协议和治理证据，不形成上游硬依赖。

### D2：MVP 使用 `node:sqlite`，以适配层保留替换能力

MVP 采用 Node 22 自带 `node:sqlite`，要求经过当前 Node 小版本验证；所有数据库访问经过单一存储适配层。它已在当前环境验证 FTS5、trigram、备份和并发，且无原生 npm 绑定安装门槛。

`better-sqlite3` 因本机缺少可用 native binding，不作为本变更依赖；其运行时与离线打包证据保持未决。公开发布前必须单独完成 Node 升级、三平台和打包硬化，不能把实验性 API 警告隐瞒为稳定承诺。

备选“立即编译 better-sqlite3”会增加 MSVC、prebuild 和离线安装成本，阻碍新会话先完成本地 MVP，因此不选。

### D3：SQLite 是唯一运行真相源，投影是派生物

核心表按以下职责划分，名称可在实现中调整但边界不得合并：

- `spaces/projects/devices/agents`：受约束的作用域主体与自定义空间。
- `memories`：当前记录头、当前修订、状态、作用域与权威级别。
- `memory_revisions/sources`：不可变修订、来源、证据和 supersedes 关系。
- `import_archives/import_items`：不可变来源快照、内容哈希和未验证导入项。
- `plans/plan_operations/approvals`：规范化计划、操作、目标修订、哈希和一次性审批。
- `conflicts/tombstones`：并发双方证据与可审计遗忘。
- `outbox_jobs`：本地可靠后台任务、尝试次数、下次重试和最后错误。
- `managed_blocks/device_installations`：投影与宿主配置所有权、目标哈希、备份和克隆身份证据。

所有写操作在本地事务中同时更新记录、审计和所需 outbox；不得先写远端再补本地状态。Markdown、检索索引和缓存都能从权威库重建。

### D4：作用域是统一策略对象，不是标签集合

定义规范化 `Scope = {space, project?, device?, agent?, sync_policy}`。预设只是构造器，自定义空间必须满足命名、所有者、默认同步策略和允许字段约束。

每次写入生成不可变作用域快照；检索、详情、导出、投影与 outbox 构造必须调用同一策略入口。`local_only` 与设备限定在上行任务生成前物理排除，而不是上传后依赖读取端过滤。作用域收窄只影响后续任务，不宣称撤回既有导出或云端历史。

### D5：中文检索采用 trigram + 有界 LIKE 回退

保留原始正文，FTS5 trigram 服务三字及以上子串与拉丁文本；两字中文和 trigram 不适合的短查询使用带作用域前置过滤、结果上限和超时预算的 LIKE 回退。应用层 bigram 不作为首版必需索引，因为 M0 单独使用未覆盖完整集合。

候选与未验证导入默认不混入活动记忆结果；确需检索导入档案时使用独立入口并清楚标识。更大语料的性能门槛留给实现测试，不能用 40 条合成记录推导无限规模性能。

### D6：审批由本地用户通道签发，MCP 只消费结果

当前 Agent 可生成规范化 `OnboardingPlan`，包含来源快照、操作、目标修订、作用域和内容哈希。系统生成 `plan_id/plan_hash` 与待审批差异。

用户通过独立本地 CLI 或后续本地确认界面完成审批；审批绑定计划哈希、目标修订、单次使用和有效期。MCP 请求里的 `approved/user_confirmed` 字段不被信任。Agent 只拿到 `approval_id` 后请求应用，存储层再次校验计划未变、目标未变、未使用且未过期。

这避免把“Agent 自称用户同意”误当授权，也使用户可以在另一终端完成确认。首版不引入常驻 HTTP 服务。

### D7：初始化分档案与晋升两层

发现适配器只访问明确允许的公开路径并读取元数据；正文只有用户勾选后才进入不可变快照。快照导入先形成 `imported_unverified + local_only` 档案，立即可本地检索和导出，不等模型整理。

当前 Agent 按批次读取已授权输入，输出 `add/merge/keep_both/skip` 计划。秘密扫描和注入处理在批次交给 Agent 前执行，应用时再次执行。批次进度、来源哈希和幂等键落库，会话中断后可续跑。

### D8：原生记忆默认 observe/router，配置修改独立授权

`observe` 不写原生文件；`router` 只写唯一受管区块，表达“跨设备共享记忆走 MCP，原生保留私有草稿”。`mcp-primary` 仅准备备份和公开手动步骤，不伪造已关闭原生记忆。

配置适配器遵循 `plan → approve → apply → doctor → uninstall`：优先使用公开 CLI 或公开 JSON 文件，保留未知字段与其他服务器，同名外来条目硬冲突。WorkBuddy UI、Copilot 私有 Memory 等无公开写接口的边界只提供手动指引或显式导入，不逆向实现。

### D9：MCP 是短生命周期接口，独立 worker 拥有后台任务

MCP stdio 只执行有界本地读写和任务入队，退出前不要求完成同步、抽取或维护。`cairn worker run-once` 与显式 CLI 后续处理 outbox；默认不安装 SessionStart/SessionEnd 同步 hook。

所有外部等待在未来都必须有 AbortSignal、超时、重试上限和退避；本变更先用故障注入 worker 验证崩溃、超时与进程退出不会影响模拟 Agent 会话。stdio stdout 仅由 MCP SDK 写协议，应用日志统一走 stderr/文件。

### D10：测试证据与可观测性先于功能扩张

使用 Node 测试运行器和合成 fixtures，测试分层为存储、检索、治理、初始化、配置、MCP SDK 合同和故障隔离。每个批次输出机器可读结果，0 tests/0 assertions 不作为成功。

本地审计事件记录计划、审批、配置备份、作用域排除、恢复与错误类别；日志默认不记录记忆正文和秘密。`doctor` 报告真实能力等级：prototype、fixture-only、real-cli-tested、blocked，禁止统一写成“已兼容”。

## Risks / Trade-offs

- [Node 自带 SQLite 仍有实验性警告] → MVP 锁定已验证 Node 小版本、集中适配层；公开发布前另做升级与跨平台硬化。
- [LIKE 回退在大数据量下可能变慢] → 作用域先过滤、限制查询长度与结果数、设置预算并记录耗时；后续依据真实规模评测优化。
- [自然语言路由可能被宿主忽略] → 只把它当行为提示；隔离、审批和删除始终由本地核心强制执行。
- [秘密正则可能漏检] → 默认未验证导入不上行、日志不回显正文、应用前复检；安全 fixtures 只证明覆盖已知形态。
- [不同 Agent 公开能力差异大] → 适配器显式声明能力等级，无公开接口时降级为手动导入/投影，不实现虚假兼容。
- [计划审批增加首次使用步骤] → 导入档案先可用，分批展示差异，只对晋升与配置修改要求确认，避免逐条审批。
- [本地 outbox 可能被误解为已支持云同步] → 首版只提供本地任务边界和远端能力探测接口，doctor 明确 remote=not_configured/not_tested。

## Threat Model

- 恶意记忆或导入正文：按不可信数据处理，不执行其中命令；投影不授予权限。
- 秘密外泄：进入 Agent、日志、投影和 outbox 前分别阻断；报告中只保留类型与位置摘要。
- 越权检索/导出：所有入口调用同一作用域策略，负向测试覆盖替代入口。
- 伪造审批与计划篡改：本地签发一次性审批，规范化哈希、目标修订和有效期重检。
- 配置与路径攻击：允许根目录、拒绝越界符号链接、原子写入、目标哈希、备份和外来同名冲突。
- 设备克隆与旧修订：克隆身份暂停写入；修订链识别并发，旧内容不得覆盖新状态。
- 半迁移与半应用：事务、幂等键、备份恢复和故障注入验证。

## Migration Plan

1. 在新项目建立空核心与 v1 迁移，不读取其他项目数据库；仅迁移 M0 的公开 fixtures 和测试证据。
2. 先实现显式记忆、检索和备份，再接治理与初始化，最后接 MCP/CLI 和投影；每一步保持可回滚。
3. 所有数据库迁移在事务和备份后执行；失败则恢复备份并保留明确错误，不启动正常读写。
4. 宿主配置只在合成 HOME 默认测试；真实修改必须重新执行计划、独立审批和备份。
5. 卸载时删除本产品 MCP/受管区块并恢复未变化目标的原字节；数据库可保留、导出或由用户另行明确删除。
6. 本变更无云端写入，回滚只涉及本地库、配置和派生投影；未来云同步另设代次和远端回滚方案。

## Verification Evidence

实现阶段至少保留：迁移/备份恢复报告、中文检索结果、4 进程写入计数、MCP initialize/list/call/cancel/timeout/disconnect 结果、初始化审批负向测试、临时 HOME 配置差异、后台故障下 Agent 会话存活证明和测试清单。真实云端、其他操作系统和未安装宿主继续标为未验证。

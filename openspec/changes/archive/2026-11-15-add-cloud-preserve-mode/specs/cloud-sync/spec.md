## REMOVED Requirements

- **Requirement: local_only 物理排除不变**（由「设备限定内容的云端保管模式（双模）」取代：物理排除成为默认关闭保管模式下的行为，不再是唯一语义）

## ADDED Requirements

### Requirement: 设备限定内容的云端保管模式（双模）

系统 SHALL 支持 vault 级保管模式开关（默认关闭）。

关闭时：`syncPolicy = local_only` 与设备限定内容 MUST 在打包前被物理排除（延续既有语义），且 MUST 可通过列举真实远端对象独立验证；project-global 等非个人全局内容的上行任务 MUST 完成并写审计，MUST NOT 产生远端事件。

开启时：设备限定内容与项目内容 SHALL 以密文上行到**本设备的保管链**（`preserve/<deviceId>`），每条事件 MUST 携带归属设备标签与作用域描述符；无论何种模式，云端对象 MUST NOT 出现明文。

#### Scenario: 关闭模式远端无本地内容

- **WHEN** 保管模式关闭的设备 push 后列举远端前缀全部对象并解密检查
- **THEN** 不存在包含设备限定记忆内容的任何 chunk

#### Scenario: 开启模式设备限定内容密文上云

- **GIVEN** 保管模式开启
- **WHEN** 设备 A 写入一条 device-local 记忆并 push
- **THEN** A 的保管链出现携带归属设备标签与作用域描述符的密文事件，明文不出现在任何云端对象

#### Scenario: 非归属设备不物化

- **GIVEN** 保管模式开启，设备 A 的保管链含 device-local 内容
- **WHEN** 设备 B 执行 pull
- **THEN** B 不拉取 A 的保管链，本地不产生该内容的任何记忆或作用域行

#### Scenario: 模式与状态如实可见

- **WHEN** 执行 doctor 或 status
- **THEN** 输出包含当前保管模式与各链的同步状态

### Requirement: 保管链与物化过滤

保管模式开启后，每台设备 SHALL 维护自己的保管链（`preserve/<deviceId>`），承载该设备的设备限定与项目内容；个人全局内容仍走个人链。`agent-private` 与 `session-ephemeral` 内容 MUST NOT 上云（任何模式下）。

pull SHALL 应用物化过滤：个人链的个人全局内容物化到本地；本设备保管链内容物化回本机；其他设备的保管链 MUST NOT 被拉取。旧版本设备 MUST NOT 受影响——它们不请求 preserve 前缀，个人链行为与既有版本一致。

#### Scenario: 设备找回

- **GIVEN** 保管模式开启，设备 A 本地数据目录丢失但 deviceId 未变
- **WHEN** 设备 A 重新 pull
- **THEN** 个人全局内容与保管链内容均恢复到本地

#### Scenario: 旧版本对端不受影响

- **GIVEN** 云端同时存在个人链与保管链
- **WHEN** 一台 0.6.x 旧版本设备执行 pull
- **THEN** 它只消费个人链，行为与本变更前完全一致，不报错、不卡链

#### Scenario: 保管链不回流他人

- **WHEN** 设备 B 执行 pull
- **THEN** B 只拉取个人链与 B 自己的保管链，A 的保管链对象不被下载

## MODIFIED Requirements

### Requirement: 迁出事件的通知语义

当一条已同步到个人全局链的记忆迁出该链（迁往项目作用域、设备限定作用域，或其他任何去向）时，系统 SHALL 向个人链上行一条「迁出」事件；迁出事件的上行 MUST NOT 依赖目的地的可同步性。

其他设备收到该事件后 MUST 把对应记忆标记为「本设备不再持有」，MUST NOT 物理删除它，MUST NOT 继续把它的新修订当作活动内容呈现。该标记 MUST 可被审计；MUST 与「遗忘（tombstone）」区分——迁出不是删除，用户在迁出设备上仍有该记忆。

#### Scenario: 另一台设备收到迁出事件

- **GIVEN** 设备 A、B 同步过同一记忆
- **WHEN** A 把该记忆迁出个人全局链并 push
- **THEN** B 收到迁出事件后把该记忆标为不再持有，不删除数据，检索不再返回它

#### Scenario: 迁入不可同步作用域同样通知

- **GIVEN** 设备 A、B 同步过同一记忆
- **WHEN** A 把该记忆迁入项目作用域（该内容不在个人链物化）并 push
- **THEN** B 收到迁出事件并把该记忆标为不再持有——通知不因目的地不可同步而缺失

#### Scenario: 迁出不等于遗忘

- **WHEN** 一台设备收到迁出事件
- **THEN** 该记忆不产生墓碑记录，遗忘时间线不被改动

#### Scenario: 迁出后重新迁回

- **GIVEN** 记忆已被迁出并通知过对端
- **WHEN** 在该设备上把记忆迁回个人全局链并 push
- **THEN** 对端重新视为持有者，内容按正常修订链同步

### Requirement: 上行入队完备性

对任何一条记忆，系统 SHALL 在其**被创建、正文被修改、被遗忘、或作用域迁移**时产生上行待办任务，路由规则如下：个人全局内容 → 个人链；保管模式开启时，设备限定与项目内容 → 本设备保管链；保管模式关闭时，非个人全局内容 MUST 在入队前被物理排除（延续既有语义）。作用域迁移涉及个人链时，MUST 同时产生个人链的迁出任务与新空间可发布时的上行任务。

该要求 SHALL 对**所有**写入入口一致成立，包括 CLI / MCP / 本地控制台 / 治理计划应用（`applyPlan`）与自动整理。系统 MUST NOT 在拉取路径上产生上行任务。

#### Scenario: 治理计划应用后记忆进入上行队列

- **GIVEN** 一条作用域为 `personal-global` 的待应用计划，其操作包含新增记忆
- **WHEN** 用户消费审批并应用该计划
- **THEN** 该新增记忆存在一条上行待办任务，且任务的实体标识等于该记忆标识

#### Scenario: 保管模式下设备限定写入入队

- **GIVEN** 保管模式开启
- **WHEN** 一条 device-local 记忆被创建
- **THEN** 它存在一条路由到本设备保管链的上行待办任务

#### Scenario: 关闭模式下设备限定写入不入队

- **GIVEN** 保管模式关闭
- **WHEN** 一条 device-local 记忆被创建
- **THEN** `outbox_job` 中不存在以该记忆为实体的任何行

#### Scenario: 自动整理产出的记忆与手工写入等价

- **GIVEN** 自动整理（策略预授权）被触发
- **WHEN** 该轮整理新增记忆若干条
- **THEN** 每条按路由规则应上行的记忆都各自存在一条上行待办任务，数量与写入入口无关

#### Scenario: 拒绝候选与遗忘产生同形上行

- **GIVEN** 一条作用域允许上行的候选记忆与一条同作用域的活动记忆
- **WHEN** 用户拒绝该候选，并另行遗忘那条活动记忆
- **THEN** 两条记忆各自存在一条墓碑语义的上行待办任务，语义与既有遗忘路径一致

#### Scenario: 设备限定内容不产生上行任务

- **GIVEN** 保管模式关闭，一条作用域为 `device-local` 或 `sensitive` 的内容经由治理计划写入
- **WHEN** 计划应用完成
- **THEN** 该记忆存在且写入成功，但 `outbox_job` 中不存在以该记忆为实体的任何行

#### Scenario: 迁出个人链产生迁出任务

- **GIVEN** 一条已同步的 `personal-global` 活动记忆
- **WHEN** 它被迁移到项目作用域
- **THEN** 产生一条固化来源为个人链的迁出任务，不因目的地不可同步而缺失

#### Scenario: 拉取不产生上行

- **GIVEN** 本地库为一个可读写的权威副本
- **WHEN** 执行 `cairn sync pull` 并应用了远端事件
- **THEN** 本次拉取前后上行待办数量不变

### Requirement: 冷启动对账

系统 SHALL 提供本地对账入口 `cairn sync backfill`，发现并补齐「允许上行、但当前不存在上行待办任务」的活动记忆：个人全局内容 → 个人链；保管模式开启时，设备限定与项目内容 → 本设备保管链。保管模式关闭时，非个人全局内容 MUST NOT 出现在候选列表中。

系统 SHALL 同时发现并补齐**存量迁出通知缺口**：曾推送到个人全局链（同步元数据存在）、现已不在个人全局作用域、但从未产生过任何迁出任务的活动记忆——本变更之前的版本迁移到可上行目的地时不产生迁出通知，这些记忆的补发使对端残缺副本自动收敛。已有过迁出任务（不论状态）的记忆 MUST NOT 重复补发。

该命令 MUST 默认只读（dry-run），仅在显式指定应用参数时才写入；MUST 幂等；MUST 只写本地待办队列，MUST NOT 与云端发生任何网络交互；MUST 以机器可读形式报告候选数、新增数、已存在数与被排除数（按链分列），以及迁出通知补发数。

#### Scenario: 只读预演不改变库

- **GIVEN** 库中存在若干应上行但未入队的记忆
- **WHEN** 执行 `cairn sync backfill` 且未指定应用参数
- **THEN** 先后的 `outbox_job` 行数与内容完全相同，输出报告候选条数，并以成功退出码结束

#### Scenario: 应用后缺口归零

- **GIVEN** 库中存在 N 条应上行但未入队的记忆
- **WHEN** 执行 `cairn sync backfill --apply`
- **THEN** 输出报告新增 N 条（按链分列），且再次执行 dry-run 时候选数为 0

#### Scenario: 保管模式开启后存量上链

- **GIVEN** 保管模式开启，库中存在从未上云的设备限定与项目内容
- **WHEN** 执行 `cairn sync backfill --apply`
- **THEN** 它们各自产生路由到本设备保管链的待办任务，再次 dry-run 时候选数为 0

#### Scenario: 被排除内容不计入缺口

- **GIVEN** 保管模式关闭，库中存在作用域为 `device-local` 的活动记忆
- **WHEN** 执行 `cairn sync backfill`
- **THEN** 该记忆不出现在候选列表中，也不产生任何 `outbox_job` 行

#### Scenario: 重复应用幂等

- **WHEN** 连续两次执行 `cairn sync backfill --apply`
- **THEN** 第二次的新增数为 0，`outbox_job` 中不存在重复的待办任务

#### Scenario: 对账不触碰云端

- **GIVEN** 本地已配置远端但网络不可达
- **WHEN** 执行 `cairn sync backfill --apply`
- **THEN** 命令仍以成功退出码结束，且不产生任何网络请求

#### Scenario: 存量迁出通知补发

- **GIVEN** 一条记忆曾推送到个人全局链（同步元数据存在），其后在本变更之前的版本中被迁移到非个人全局作用域（旧语义不产生迁出任务）
- **WHEN** 执行 `cairn sync backfill --apply` 并推送
- **THEN** 该记忆产生一条固化来源为个人链的迁出任务，推送后对端把该记忆标记为不再持有；重复对账不再补发

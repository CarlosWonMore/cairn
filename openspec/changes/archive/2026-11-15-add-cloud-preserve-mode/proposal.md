## Why

2026-11-14～15 的两设备事故暴露了一个根本矛盾：同步链只认 `personal-global` 空间，push 对其他内容**静默完成任务、不发事件**（源码注释自认"作用域迁移属后续边界"）。实测后果：主设备把 27 条记忆迁入 project-global 并更新 3 条内容后，对端**永远不知情**，27 条旧内容残缺地 active 在对端；作用域调整（rescope）这个最需要全端一致的操作，恰恰是同步盲区。

讨论后确定的方向（推翻既有"物理排除"边界的一个子集）：**云端做全量密文保管，物化过滤放在拉取侧**——

- 每一个记忆都密文上云，携带**归属设备标签**与作用域描述符（来源可追溯）
- 物化过滤决定落地：只有 personal-global 物化到其他设备；设备限定与项目内容在云端有保管、在别机**不物化**
- 作用域调整作为普通事件传播到所有设备——持有副本的设备自适应调整，没持有的无感

相对"项目订阅链"方案（已撤的 add-project-space-sync）：省去项目身份桥接、订阅匹配、多链管理三大复杂块；顺带获得全量密文异地保管与设备重装找回能力；未来想让项目记忆落地某设备时协议零变化。

## What Changes

- **vault 级保管模式开关**（默认关闭）：关闭 = 既有物理排除语义不变；开启 = 设备限定与项目内容以密文上行到**本设备的保管链**（`preserve/<deviceId>`），个人链语义不变。
- **事件携带作用域描述符 + 拉取侧物化过滤**：个人全局物化到本地；本设备保管链物化回本机；其他设备的保管链不拉取。非归属设备的设备限定内容 MUST NOT 物化。
- **记忆携带归属设备并可用于展示与过滤**：本机创建记录本机、同步到达记录来源设备，既有记忆如实展示「未知」；控制台记忆卡片就近展示归属设备徽章，过滤器新增「来源设备」条件（与既有作用域过滤并列，静态导出页同构支持）；归属设备仅用于展示与过滤，不参与读取授权。
- **作用域调整传播（两种模式都生效，本次事故的核心修复）**：记忆迁出个人全局链时 MUST 上行迁出事件（无论去向是项目还是设备限定）——对端自动把残缺副本转"不再持有"，不再需要人工清理。
- **消灭静默完成**：push 对不可路由任务 MUST 完成并写审计。
- **backfill 多链**：开启保管模式后，对账覆盖保管链（存量 27 条 + 设备限定内容由此首次上链）。
- **可观测**：doctor/status 汇报模式、各链 headSeq/游标/缺口。
- **边界重写**：cloud-sync 规格的「local_only 物理排除不变」要求由「设备限定内容的云端保管模式（双模）」取代；AGENTS.md 安全与授权行、`docs/cairn-security.md` 同步改写（用户已确认推翻该边界）。
- 不变：E2EE 体系（不引入新密钥材料）、chunk/manifest 协议与 CAS、设备备份通道、治理链路、`agent-private` 与 `session-ephemeral` 永不上云（即使保管模式开启）、旧版本兼容（0.6.x 对端不请求 preserve 前缀，个人链行为不变）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `cloud-sync`：新增保管模式（双模）与保管链；迁出事件完整性；上行入队完备性扩展到保管模式；backfill 多链；物化过滤。
- `memory-store`：记忆携带归属设备（记录、载荷暴露、不参与授权）。
- `local-console`：记忆视图新增「来源设备」过滤条件与归属设备徽章（工作台与静态导出同构）。

## Impact

- **代码**：`src/sync/push.js`（保管链路由 + 迁出完整性 + 消灭静默分支）、`src/sync/apply.js`（物化过滤 + 作用域描述符 + 来源设备记录）、`src/sync/pull.js`（个人链 + 本设备保管链）、`src/sync/backfill.js`、`src/sync/events.js`（事件作用域描述符与归属设备标签）、`src/store/`（schema v7：memory 增 origin_device_id 及迁移）、vault 配置与 doctor/status、控制台记忆视图（设备徽章 + 来源设备过滤 + `/api/memories` device 参数）、CLI help 文案修正。
- **测试**：单测（模式开关、路由、物化过滤、迁出完整性、归属设备记录）+ e2e fake backend 双设备（保管模式开/关、残留副本自动收敛、设备找回）+ 变异对照；真实云端两设备验证仍单独授权。
- **迁移**：schema v6 → v7（memory 增 `origin_device_id` 列，存量行置空表示「未知」）；存量内容靠 backfill 首次上链；默认关闭，既有用户除 schema 版本号外零行为变化。
- **文档**：`docs/cairn-sync.md`、`docs/cairn-security.md`、AGENTS.md 边界行、README。
- **安全姿态**（用户已确认）：vault 密钥泄露的爆炸半径从"个人全局"扩大到"全部记忆"（仅对该 vault 且仅在开关开启时）；对端与本机共享 vault 密钥，被入侵的对端可解其他设备保管链的密文。

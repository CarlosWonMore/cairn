# Proposal: 设备限定记忆的云端加密备份

## Why

用户 2026-11-11 的原话：

> 是否可以考虑 设备记忆，也同步到云端，但是只跟本设备同步？

追问后确认真实意图是：**容灾 + 换设备迁移**。

## 为什么不能真的「同步」

这在本项目的定义层是矛盾的，有两个硬约束：

| 约束 | 出处 |
|---|---|
| 设备绑定作用域的 `syncPolicy` 必须是 `local_only` | `src/core/scope.ts:203` |
| `encrypted` 同步要求 `deviceId` 为 `all` | `src/core/scope.ts:207` |

而且同步的语义是「让对端拥有等价副本」。如果只有本设备能读，那它不叫同步，叫**备份**。

## 现状的缺口

`cairn backup` 已经能产出事务一致快照（`src/store/backup.ts`，VACUUM INTO + sha256），但**只存在本地** `~/.cairn/backups/`。

所以现在：

- 本机硬盘坏了 → `device-local` 记忆全丢（这些记忆按设计永不上云）
- 换新电脑 → 只能靠手动拷贝备份文件

这正是用户想解决的问题。

## What Changes

- **加密备份上传**：把 `cairn backup` 产出的快照用 vault 密钥加密后上传到远端（syncd / OBS），路径含设备标识。
- **按设备隔离**：备份只能由**生成它的设备**下载恢复；其他设备即使拿到密文也解不开（用设备专属密钥派生）。
- **保留策略**：默认保留最近 N 份（默认 5），超出按时间淘汰。
- **命令**：`cairn backup --upload` / `cairn backup --list-remote` / `cairn restore --from-remote <id>`。
- **不进入同步链**：走独立的对象前缀，与 `personal-global` 的事件链互不干扰。

### 明确不做的事

- **不放开 `local_only` 约束**。设备限定内容仍不上事件链；这里走的是**整库快照备份**通道，语义不同。
- **不做自动定时上传**。与「同步退出会话关键路径」一致，由用户显式触发（或他自行用系统计划任务）。
- **不做增量备份**。快照是全量；本项目库体积（当前 2.6 MB）远未到需要增量的程度。
- **不做跨设备共享备份**。设备 A 的备份设备 B 解不开——这是特性不是缺陷。

## Impact

- Affected specs: `memory-store`（备份）、`cloud-sync`（独立对象前缀与密钥隔离）
- Affected code: `src/store/backup.ts`（加密）、`src/sync/`（新增 backup store 通道）、`src/interfaces/cli/main.ts`
- 不涉及数据库迁移
- 回滚：不上传即回到现状；已上传对象可保留或忽略

## 风险与回滚

| 风险 | 处置 |
|---|---|
| 备份密文泄漏到其他设备 | 用设备专属密钥派生加密；其他设备无对应私钥，拿到也解不开 |
| 上传把敏感内容带到云端 | 端到端加密，云端只见密文（与现有同步同一套 XChaCha20-Poly1305） |
| 备份撑爆远端空间 | 保留策略默认 5 份；上传前报告体积；超过阈值要求 `--force` |
| 恢复覆盖当前库 | `restore` 必须先备份当前库，且要求显式 `--force`；默认恢复到新路径 |

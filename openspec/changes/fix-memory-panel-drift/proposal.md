# Proposal: 修正记忆面板的「注入计数」与「活动记录」漂移

## Why

用户 2026-11-10 报告：面板左下「本会话注入的记忆」列出 25 条，但右侧活动记录**每一条都写「注入0」**，且每条都是 `(nothing_new)`。用户据此怀疑这些记忆其实没被注入、面板在虚报。

**实测结论：注入是真的，虚报不成立；错的是活动记录的计数与措辞。** 证据链：

1. 会话转录（`session.v4.jsonl.zstd`，690 个 zstd 帧解出 1675 行）里有 **6 条** `user/message`、`source.kind = 'cairn-memory-injection'` 的真实注入消息，逐条带 3–5 条记忆，合计 **25 条记忆行**；
2. 面板 `sessionInjected` 恰好 **25 条**，与转录逐条比对：**0 条多余、0 条缺失**；
3. 所以「本会话累计注入」这一栏是**准确的**。

真正的问题在右侧活动记录，有三个可复现的缺陷：

### 缺陷 A：`nothing_new` 被写成「注入0」，与事实相反

`agent/pre-step` 每走一步就调用一次 `runOnce`。同一段记忆在本会话**第一次**被注入后进入去重集合，此后每步都返回 `nothing_new`。而活动记录用 `out.selected` 当注入数——`nothing_new` 分支返回的 `selected` 恒为 0：

```ts
// plugin/dsh/src/index.ts:120
return { injected: false, reason: 'nothing_new', text: '', selected: 0, truncated: 0, injectedIds: [] };
```

于是同一段时间轴上出现两个互相矛盾的数：左栏「25 条已注入」、右栏「注入0 × 87 次」。**用户看到的是后者**，因为它是逐行重复的。

更糟的是措辞：`nothing_new` 的真实语义是「**命中了 5 条，但本会话都已注入过，本轮不重复**」——这在日志里读起来和「没找到任何东西」一模一样。

### 缺陷 B：活动记录被高频空步淹没，真实注入被挤出行

环上限 120 条，但 `nothing_new` 每步一条。实测当前 ring 里 **120 条中只有 3 条带 `items`**（真正注入的那几次），其余 117 条是空步。面板默认只显示最近 15 条 ⇒ 用户永远看不到那 3 条。

### 缺陷 C：去重状态没有随会话压缩重置

`agent-interfaces` 的既有要求写的是「同一会话内已注入过的记忆 MUST NOT 重复注入，**直到会话上下文被压缩或重置**」。但 `resetSession()` 在**全仓零调用点**（grep 只有定义处 `index.ts:136`）。会话压缩后上下文里已经没有那些记忆了，插件却仍然认为「已注入过」——于是长会话越用到后面，越不可能再注入任何东西，表现为大面积 `nothing_new` + 永远同样的候选 5 条。

### 为什么现在做

用户已经把「只在登录时 + 手动」的同步设置定了，接下来面板是唯一的可见性窗口。**一个会说反话的活动日志比没有日志更糟**——它会让人怀疑整个记忆层的正确性（本次就是这样）。

## What Changes

- **活动记录按语义区分三种召回结果**，不再共用「注入0」措辞：
  - 真注入了 N 条 → `注入 N`；
  - 命中但全部已在会话内注入过 → **`已去重`**（并报告本会话累计已注入条数），措辞里 MUST 能看出「找到了、只是不重复」；
  - 真的没找到 → `未命中`（候选 0）。
- **空步折叠**：连续相同结果的空步（主要为「已去重」）在活动记录里合并为一条并计数，MUST NOT 占据环里绝大多数槽位把真实注入挤出去。折叠后 MUST 仍能看出这段空步持续多久/多少步。
- **去重状态随会话压缩重置**：监听宿主提供的压缩/重置信号，重置本会话的去重集合与「本会话累计注入」。若宿主不提供可挂钩的信号，MUST 在文档里写明该边界并以「会话 id 变化」作为唯一的重置时机。
- **左栏补一行口径说明**：列出本会话累计注入条数，并说明它与右侧活动记录的关系（右侧记录每步、左侧按 id 去重），避免再次被误读为「面板在虚报」。

### 明确不做的事

- **不改注入逻辑本身**：注入内容、去重集合、预算、排序全部不动。已经验证过与转录逐条一致，没有理由改。
- **不把记忆正文或摘要写进落盘活动日志**（`activity-dsh.jsonl`）。既有要求 `agent-interfaces`「日志 MAY 记录时间/类型/动作摘要/会话标识，MUST NOT 含记忆内容（含摘要）」继续生效。
- **不改 MCP / 内核**。本次全部是插件侧（`plugin/dsh/`）。
- **不做「关掉自动召回」**。空步多不是关掉召回的理由，是折叠与措辞的问题。

## Impact

- Affected specs: `agent-interfaces`（活动记录语义、空步折叠、去重重置时机）
- Affected code: `plugin/dsh/src/index.ts`（`runOnce` 返回语义、`pushActivity` 折叠、去重重置挂钩）、`plugin/dsh/src/recall.ts`（`InjectionDecision` 增加可区分的 reason）、`plugin/dsh/src/client.js`（左栏口径行）
- Affected tests: `plugin/dsh/tests/injector.test.ts`、`plugin/dsh/tests/panel-render.test.ts`、`plugin/dsh/tests/recall.test.ts`
- 无数据库迁移、无 API 破坏性变更（`/usage` 只增字段）
- 回滚：改回 `plugin/dsh/src` 即可；插件从 `dist` 加载，重建后回退 dist 即恢复

## 风险与回滚

| 风险 | 处置 |
|---|---|
| 改动把真实注入也折叠掉，导致信息丢失 | 折叠**只针对「已去重/未命中」这类未产出生效注入的步**；凡 `items` 非空的条目 MUST 永远单独成条 |
| 「已去重」措辞仍被误读 | 措辞里必须出现本会话累计计数，让用户能对上左栏数字 |
| 宿主不提供压缩信号，改了个不触发的东西 | 先查 asar 确认事件名**真实存在**；查不到就如实降级并在文档写明，不许假设 |

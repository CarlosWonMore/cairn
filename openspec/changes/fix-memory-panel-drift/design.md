# Design: 修正记忆面板的注入计数与活动记录漂移

## 上下文（实测，2026-11-10）

用户报告「左栏 25 条、右栏全写注入 0」。三处证据已交叉核对：

| 来源 | 数据 |
|---|---|
| 会话转录（690 zstd 帧 → 1675 行） | 6 条 `user/message` + `source.kind=cairn-memory-injection`，合计 **25 条记忆行** |
| `/usage` 的 `sessionInjected` | **25 条**，与转录逐条比对：0 多余 / 0 缺失 |
| `/usage` 的 `recent`（120 条环） | 仅 **3 条**带 `items`，其余 117 条是 `nothing_new` |

结论：**注入是真的，左栏是准的，错在右栏的计数与措辞**，以及环被空步挤占。

## 决策

### D1：区分三种结果靠 `runOnce` 返回真实语义，不靠调用方猜

现状 `runOnce` 的返回把两件事混在 `selected: 0` 里：

```ts
// nothing_new 分支：命中过、都去重了 → selected 恒 0
return { injected: false, reason: 'nothing_new', ..., selected: 0, ... };
```

**决策：新增可区分的 reason，并在返回里带上「本轮候选数」与「去重挡掉几条」。**

具体形状（向后兼容，只增字段）：

```ts
interface InjectionOutcome {
  injected: boolean;
  reason: 'ok' | 'disabled' | 'empty_message' | 'all_seen' | 'miss' | 'recall_failed';
  /** 本轮召回候选数（过滤前）。 */
  candidates: number;
  /** 本轮因会话内去重而未注入的条数。 */
  deduped: number;
  /** 本轮本会话累计注入条数（新增，供活动记录写进措辞）。 */
  sessionTotal: number;
  ...
}
```

判定顺序（**先判候选再判去重**，否则「候选 0」会被误标成「已去重」）：

1. `candidates === 0` → `miss`（未命中）
2. `deduped > 0 && includedIds.length === 0` → `all_seen`（已去重）
3. `includedIds.length > 0` → `ok`

### D2：折叠放在 `pushActivity` 里，按「连续同类未产出生效注入」聚合

**决策：不改 activity 的条目形状，改为在写入时与上一条比较：若上一条是同 reason 的「未产出生效注入」记录，则把它的 `count` 加一并刷新 `t`（保留 `firstT`），不新增条目。**

为什么不做「读取时聚合」：读取时聚合要在 client 与 host 两处各实现一遍，且 `recent` 的分页/选中/高亮都按条目 id 索引，聚合会破坏 `entryKey` 的稳定性（用户点选一条高亮后，下一次轮询聚合结果可能变化，高亮跳走）。写入时聚合让环里的每条都稳定不变。

两条硬约束：

- **带 `items` 的条目永不合并**（spec「真实注入不被折叠」）；
- 折叠条目保留 `firstT` 与 `t`，面板显示 `N 次 · 最近 HH:MM`，用户能算出距上次真实注入多久。

### D3：去重重置——先查宿主有没有信号，查不到就诚实降级

既有要求写「直到会话上下文被压缩或重置」，但 `resetSession` 全仓零调用。

**决策：分两步，且第二步以第一步的实测结果为前提。**

1. 在 `app.asar` 中确认宿主是否暴露压缩/重置事件（候选名：`session/compact`、`session/compacted`、`agent/compact`）。已 grep 到 `compaction` 相关标识 2600+ 处、`agent/pre-step` 80 处，但**尚未确认存在可供插件 `hooks.on` 监听的事件名**。
2. 有 → 挂上并调 `st.injector.resetSession()`；没有 → **不发明事件名**，改为文档如实声明「仅在会话 id 变化时重置」，并在 spec 的 Scenario 里保留该边界。

> 这一步**必须由实现者去 asar 里查证**，不许凭命名习惯猜。查不到就写"查不到"，这是验收项。

### D4：左栏口径行放在状态区底部，一行字解决误读

左栏标题已有「去重 · 本会话累计」，但没说清与右栏的关系。**决策：在左栏条目列表下方追加一行小字**，例如：

```text
25 条 · 右栏记录每一步，本栏按去重累计
```

不新增面板区块、不加交互，一行字解决。

## 威胁模型

| 威胁 | 后果 | 缓解 |
|---|---|---|
| 折叠把真实注入吃掉 | 用户看不到真正发生了什么 | 带 `items` 的条目永不合并，单独用例钉住 |
| 「已去重」被实现成新的一种"什么都没发生" | 换汤不换药 | spec 明确要求措辞里出现累计条数；用例断言字符串不含「注入 0」 |
| 去重集合被错误地频繁重置 | 同一记忆每步重复注入，烧预算 | 重置只挂在压缩信号或会话 id 变化上；用例断言"未压缩时不重复注入"仍成立 |
| 猜一个不存在的宿主事件名 | 监听静默失效，看起来"实现了" | 实现必须给出 asar 里的查证结果（命中/未命中），未命中则降级并写文档 |

## 迁移与回滚

- 无数据迁移。`activity-dsh.jsonl` 的既有行没有 `count` 字段 → 读取时按 1 处理。
- 回滚：还原 `plugin/dsh/src` 并重建 `dist`。

## 可观测性

| 观察点 | 位置 | 期望 |
|---|---|---|
| 活动记录措辞 | 面板右栏 | 出现「已去重」而不再是「注入 0」 |
| 环里真实注入占比 | `/usage?history=1` | 折叠后带 `items` 的条目不再被空步挤出 |
| 左栏口径行 | 面板左下 | 显示累计条数 + 一行说明 |

# Proposal: 上下文压缩后重注入本会话讨论过的记忆

## Why

2026-11-10 实测：DSH 的 `compaction/end` 事件已经能挂到（插件当前只做去重回填）。

但**只清去重集合是不够的**。上下文被压缩后，先前注入过的记忆文本**已经从上下文里消失**，而插件此时只是"允许它再次被检索到"——能不能重新出现，取决于**下一步的用户消息能不能命中它**。如果用户接着问的是同一件事的后续，很可能不会命中同样的关键词，于是模型在毫无提示的情况下失忆。

社区已有实现验证这个缺口（`Phant0Meow/dsh-meow-memory`，383★，README 原文）：

> **压缩后重注入**：会话压缩后，下一轮自动重新注入长期记忆快照 + 本会话查阅过的项目全景 + **本会话写入过的记忆原文**，AI 不会因为压缩突然失忆。

而 `vectorize-io/hindsight` 的基准（sdebench，61 个真实任务）给出另一个佐证：加入记忆后**任务准确率几乎不变**（60–61/61），真正变化的是**纠正次数**（Claude Code 0.85→0.36）与**成本**（$0.445→$0.338）。也就是说，记忆的价值主要在**避免返工**——而"压缩后失忆"正是返工的主要来源之一。

## What Changes

- 插件记录**本会话涉及过的记忆**（不只是"注入过"，还包括被 Agent 通过 MCP 读过、写过的）。
- 收到 `compaction/end`（且非失败）时，除了清空去重集合，**主动重注入**本会话涉及过的记忆原文（受既有预算约束）。
- 重注入内容标注为"压缩前本会话涉及过的记忆"，与常规召回区分，避免模型误以为这是新发现的相关信息。
- 重注入**遵守既有预算**：超预算时按既有的裁剪规则处理，并在文本里写明省略条数。

### 明确不做的事

- **不做无限累积**。只重注入本会话涉及过的，不扩大到全库。
- **不改变常规召回逻辑**（`deriveQueries` / `rankHits` / 预算算法一行不动）。
- **不做"项目全景"**（meow 有，但它依赖 project 锚定体系，Cairn 当前没有等价物；留待后续）。
- **不写盘**。会话内追踪只在内存，会话结束即丢。

## Impact

- Affected specs: `agent-interfaces`（插件注入行为）
- Affected code: `plugin/dsh/src/index.ts`（会话追踪 + compaction 处理）、`plugin/dsh/src/recall.ts`（重注入渲染，复用 `renderInjection`）
- 无内核改动、无数据库迁移、无同步语义变化
- 回滚：插件配置 `reinjectOnCompaction: false` 即关闭

## 风险与回滚

| 风险 | 处置 |
|---|---|
| 重注入把上下文又撑爆 | 复用既有 `budgetBytes`；重注入单独限额（默认不超过预算的一半），超出裁剪并写明 |
| 重复注入（压缩后又常规命中同一批） | 重注入后把这些 id 重新加入去重集合，常规召回不再重复 |
| 会话涉及集合无限增长 | 内存 Map + 上限（如 200 条），超出按最近使用淘汰 |
| 模型误把重注入当成新信息 | 文本头部明确标注来源 |

# agent-interfaces Specification

## Purpose
为不同能力等级的 Agent 提供统一、可诊断、可卸载的 CLI 与 MCP 接入，并保证任何后台故障都不会破坏当前会话。

## Requirements

### Requirement: MCP stdio 协议纯净
系统 SHALL 通过标准 MCP 提供记忆与治理工具，stdio 的 stdout MUST 只包含协议消息，日志 MUST 仅写入 stderr 或文件。

#### Scenario: 初始化并调用工具
- **WHEN** 客户端执行 initialize、tools/list 和 tools/call
- **THEN** 系统返回合法协议响应，stdout 中没有日志、警告文本或非协议输出

#### Scenario: 请求超时或断开
- **WHEN** 客户端取消请求、超时或断开连接
- **THEN** 系统终止对应短操作或保留可恢复任务，不向 stdout 写入异常文本，也不影响后续本地使用

### Requirement: CLI 离线管理与机器可读结果
系统 SHALL 提供本地初始化、显式记忆管理、检索、导出、配置计划、健康检查和卸载入口，并 SHALL 以稳定退出码及可选 JSON 输出区分成功、拒绝和故障。

#### Scenario: 无模型环境执行健康检查
- **WHEN** 用户在无模型、无云端环境执行 doctor
- **THEN** 系统检查本地库、协议和配置并报告真实状态，不将可选增强缺失判为核心不可用

### Requirement: 配置合并且不侵占宿主
系统 SHALL 让配置计划默认零写入，应用前备份并仅合并本产品条目； MUST 保留未知字段和其他服务器，同名外来条目 MUST 被视为冲突。

#### Scenario: 宿主已有其他 MCP 配置
- **WHEN** 用户批准添加本产品后执行卸载
- **THEN** 系统只移除本产品条目，其他服务器和未知字段保持不变

#### Scenario: 已存在同名外来条目
- **WHEN** 配置中存在并非由本产品管理的同名服务器
- **THEN** 系统停止应用并报告冲突，不覆盖原配置

### Requirement: 后台任务退出会话关键路径
系统 SHALL 将同步、抽取、嵌入和维护放入独立 worker、显式命令或系统计划任务；默认 MUST NOT 安装阻塞式同步 hook。

#### Scenario: 后台任务超时
- **WHEN** 网络、模型、维护或 worker 超时、崩溃或返回错误
- **THEN** 当前 Agent 会话继续可用，本地操作不被撤销，后台仅留下有界重试或待处理状态

#### Scenario: MCP 进程退出
- **WHEN** MCP stdio 进程随客户端会话结束而退出
- **THEN** 系统不要求该进程完成后台同步，未完成任务之后可由独立入口续跑

### Requirement: 受管投影与防回环
系统 SHALL 仅从经过作用域过滤的当前记忆生成受管文件投影，投影 MUST 幂等、可停用、可重建，且不得被默认反向导入形成回环。

#### Scenario: 重复生成与卸载投影
- **WHEN** 用户重复生成投影后卸载
- **THEN** 重复生成不产生重复区块，卸载只移除本产品受管内容，其他说明保持不变

### Requirement: 健康检查诚实反映能力边界
系统 SHALL 区分协议可用、fixture 验证、真实 CLI 验证和未公开接口，MUST NOT 将文档支持或模拟测试报告为真实宿主认证。

#### Scenario: 宿主仅有公开文件配置
- **WHEN** doctor 检查只有文件适配证据的宿主
- **THEN** 结果显示 fixture-only 或相应有限状态，不显示为全功能或真实原生记忆已接管

### Requirement: 本地控制台入口
系统 SHALL 提供 `cairn ui` 作为可选的本地控制台入口，并 SHALL 支持 `--export <file>` 生成不启动服务的只读静态预览；两类形态 MUST 共享同一份只读数据装配逻辑，且 MUST NOT 成为其他命令的前置依赖。

#### Scenario: 控制台按需启动
- **WHEN** 用户执行 `cairn ui` 并按 Ctrl-C 结束
- **THEN** 系统正常关闭监听并以 0 退出，退出后 CLI、MCP 与库内容均与启动前一致

#### Scenario: 无服务环境导出
- **WHEN** 用户在不能监听端口的受限环境中执行 `cairn ui --export report.html`
- **THEN** 系统仍能产出完整静态预览并报告被脱敏排除的条目数

#### Scenario: 未安装可选依赖
- **WHEN** 用户仅安装发布包而未安装任何前端工具链
- **THEN** 控制台仍可用，因为其实现不依赖外部前端包与构建步骤

### Requirement: 非 JSON 插件树形态的 MCP 接入

系统 SHALL 支持宿主以非 JSON 的插件树形态登记 MCP 服务器，且该形态下 MUST 同样满足「只合并本产品条目、保留未知内容、同名外来条目为冲突」的不变量。

接入新形态 MUST NOT 引入新的运行时依赖；结构无法识别时 MUST 显式失败，MUST NOT 以「尽力猜测」的方式重写宿主文件。

#### Scenario: 首次接入插件树形态宿主

- **WHEN** 用户对以插件树形态保存 MCP 配置的宿主执行 plan 与 apply
- **THEN** 系统新增恰好一个本产品条目，宿主文件中既有的其他条目、注释与键序逐字保留

#### Scenario: 重复应用

- **WHEN** 用户对已接入的插件树形态宿主再次执行 apply
- **THEN** 系统更新或跳过本产品那一个条目，不产生第二个本产品条目，且报告内容未变化

#### Scenario: 已存在同名外来条目

- **WHEN** 插件树中已存在并非由本产品管理的同名服务器条目
- **THEN** 系统停止应用并报告冲突，不覆盖原条目

#### Scenario: 文件结构不符合预期

- **WHEN** 宿主配置文件的结构与适配器预期的形态不一致
- **THEN** 系统以配置冲突类错误终止并说明原因，不写入任何内容，也不静默降级

#### Scenario: 卸载只移除本产品条目

- **WHEN** 用户对插件树形态宿主执行卸载
- **THEN** 系统只移除本产品登记的条目，宿主中其他条目、注释与未知字段保持不变

### Requirement: 投影按宿主语义分级

系统 SHALL 依据宿主的实际注入约定选择投影形态：能承载正文的宿主投影摘要，只接受索引行的宿主仅投影索引，无公开落点的宿主不投影。

系统 MUST NOT 把正文写入约定为索引的宿主文件，MUST NOT 向无公开路径的宿主写入推测位置。

投影排序 MUST 让 `lesson` 类型优先于其他类型：它承载「曾经错了、别再犯」，最需要在会话开场被看到。

#### Scenario: 正文型宿主
- **WHEN** 宿主以文件正文形式注入记忆
- **THEN** 系统投影带 id 的记忆摘要，且总字节不超过该宿主预算

#### Scenario: lesson 优先
- **WHEN** 候选记忆中同时存在 lesson 与其他类型且预算不足以容纳全部
- **THEN** 被保留的是 lesson 类型，其余按既有排序规则裁剪

#### Scenario: 索引型宿主
- **WHEN** 宿主的约定是索引文件
- **THEN** 系统只投影「一行指针 + 一句话」，不写入记忆正文

#### Scenario: 无落点宿主
- **WHEN** 宿主没有公开的注入位置
- **THEN** 系统不写任何文件，只报告该宿主不可投影

### Requirement: 投影预算与截断如实报告

系统 SHALL 为每个宿主设定字节预算，超预算时 MUST 按确定性规则裁剪并在投影中明示被省略的条数。

#### Scenario: 超出预算

- **WHEN** 选中记忆渲染后的总量超过宿主预算
- **THEN** 系统裁剪到预算内，并在区块内写明省略条数，不得静默截断

#### Scenario: 预算内

- **WHEN** 内容在预算内
- **THEN** 系统完整投影，不出现省略提示

### Requirement: 投影内容可复现

系统 SHALL 保证同一记忆集合在相同预算下产出逐字节相同的投影，MUST NOT 让时间戳等易变值影响投影字节。

#### Scenario: 重复生成

- **WHEN** 记忆集合未变化时重复生成投影
- **THEN** 产出字节完全一致，且文件不被重写

### Requirement: 宿主插件的实时召回以 MCP 为内核

系统 SHALL 允许为特定宿主提供插件形态的实时召回，但该插件 MUST 复用现有 MCP 内核完成检索与作用域判定，MUST NOT 另行实现一套记忆存储或审批路径。

插件不可用时，系统 MUST 退化为纯 MCP 调用模式，MUST NOT 让宿主会话因此不可用。

#### Scenario: 插件正常时的召回
- **WHEN** 宿主支持 pre-step 事件且插件已启用
- **THEN** 系统在模型步骤前按当前问题召回记忆并注入，检索与过滤走与 MCP 相同的实现

#### Scenario: 插件不可用
- **WHEN** 插件未安装、加载失败或宿主版本不兼容
- **THEN** 宿主仍可通过 MCP 工具直接读写记忆，会话不中断，仅失去实时召回

#### Scenario: 注入内容同样受作用域约束
- **WHEN** 召回结果中包含 `local_only` 作用域或敏感度非普通的记忆
- **THEN** 这些记忆不进入注入内容，与投影通道的排除规则一致

### Requirement: 插件注入可关闭且不重复

系统 SHALL 允许按会话关闭插件注入；关闭后 MUST 停止注入但 MUST NOT 影响记忆的写入与其他通道。

同一会话内已注入过的记忆 MUST NOT 重复注入，直到会话上下文被压缩或重置。

去重范围 MUST 是**单个会话**：同一台设备上的另一个会话 MUST 仍可注入同一条记忆。

#### Scenario: 按会话关闭注入

- **WHEN** 用户在当前会话关闭插件注入
- **THEN** 后续步骤不再注入记忆，MCP 工具仍可用，记忆写入不受影响

#### Scenario: 同会话去重

- **WHEN** 同一记忆在连续多个步骤都被检索命中
- **THEN** 系统只注入一次，不重复占用上下文

#### Scenario: 不同会话互不影响

- **WHEN** 记忆 M 已在会话 A 注入过，会话 B 首次命中 M
- **THEN** 会话 B 仍注入 M

### Requirement: 记忆调用对用户可见

系统 SHALL 在会话界面中展示本轮的记忆召回与注入情况，含召回条数、注入条目、命中通道与预算占用。

系统 MUST 区分「未命中」「已过滤」「已注入」三种状态；MUST NOT 把「找到了但被安全规则排除」呈现为与「没有找到」相同的状态。

面板 MUST 按会话呈现，并分为左右两栏各自滚动：左侧是本会话的状态与注入过的记忆（按 id 去重、跨轮累计），右侧是本会话的活动记录（不提供条目数选择，超出高度靠滚动）。

活动记录 MUST 在自身区域内独立滚动，MUST NOT 与整个会话区共用一个滚动条。

面板 MUST 自适应宽度：空间不足时两栏上下堆叠且不横向溢出；栏宽 MUST 可拖拽（左栏 25%–75%）并记住，MUST 提供恢复默认布局的入口。

活动记录中的「自动召回」条目 MUST 可点选，选中时 MUST 高亮该次注入的记忆条目，MUST 可再次点选取消。

#### Scenario: 成功注入

- **WHEN** 本轮召回命中且注入成功
- **THEN** 面板左上方显示状态「已注入」与召回条数、命中通道、预算占用
- **THEN** 面板左下方列出本会话注入过的记忆（去重），长摘要换行而不是截断溢出
- **THEN** 右侧活动记录区独立滚动，滚动时不带动左侧状态区

#### Scenario: 未命中

- **WHEN** 本轮召回没有命中任何记忆
- **THEN** 面板明确显示「未命中」，而不是留空或显示为已注入

#### Scenario: 命中但被过滤

- **WHEN** 召回命中但命中项因作用域或敏感度被排除
- **THEN** 面板显示「已过滤」并给出被过滤的条数，MUST NOT 展示被过滤内容的正文

#### Scenario: 窄宽度下的堆叠

- **WHEN** 面板可用宽度不足以并排容纳两栏
- **THEN** 两栏上下堆叠，筛选条按钮换行显示，MUST NOT 出现横向滚动条

#### Scenario: 活动记录的浏览

- **WHEN** 活动记录条数超过可视高度
- **THEN** 用户在右侧区域内滚动查看更早的记录
- **THEN** 面板不提供「显示多少条」的选择项，也不因此隐藏任何记录

#### Scenario: 面板撑不出会话区时

- **WHEN** 宿主把视图区高度放成自适应（会话进行中），不再约束面板高度
- **THEN** 活动记录仍然在自己的区域内滚动，而不是把整个会话区撑长
- **THEN** 面板其余部分不因此被裁切或出现横向滚动条

#### Scenario: 拖拽调整栏宽

- **WHEN** 用户按住两栏之间的手柄左右拖动
- **THEN** 左栏宽度随之改变，右栏自动占据剩余宽度
- **THEN** 左栏宽度不会小于 25% 或大于 75%

#### Scenario: 记住并恢复布局

- **WHEN** 用户拖动后关闭并重新打开面板
- **THEN** 面板按上次的左右占比显示
- **THEN** 点击「重置布局」后回到默认的左右自适应宽度，且下次打开仍是默认

#### Scenario: 会话之间互不串台

- **WHEN** 用户同时开着两个会话，各自发生过记忆注入
- **THEN** 每个会话的面板只显示本会话的活动记录与注入条目
- **THEN** 在本会话点选记录时，只高亮本会话列表里的条目

#### Scenario: 点选高亮

- **WHEN** 用户点选右侧某条「自动召回」记录
- **THEN** 左侧本会话列表里属于该次注入的条目高亮显示
- **THEN** 再次点选同一条记录取消高亮

### Requirement: 面板不泄露记忆正文

面板 MUST 只展示摘要级信息，MUST NOT 展示记忆正文全文；MUST NOT 展示任何被判为敏感或设备限定内容的文本。

活动记录的落盘日志 MUST NOT 包含记忆内容——包括摘要。日志 MAY 记录时间、类型、动作摘要与会话标识。

#### Scenario: 敏感内容不出现在面板

- **WHEN** 库中存在敏感或 `local_only` 的记忆
- **THEN** 面板既不显示其正文，也不显示其摘要，只计入被过滤条数

#### Scenario: 落盘日志不含记忆内容

- **WHEN** 用户开启「落盘」并发生一次注入
- **THEN** `activity-dsh.jsonl` 里只有动作摘要与会话标识，MUST NOT 出现记忆正文或摘要

### Requirement: 注入内容不得由虚词单独驱动

实时召回 SHALL 用当前用户消息构造查询，但 MUST NOT 把高频虚词（「一个」「这个」「可以」「是否」这类）当成检索词。

一条命中 MUST 与当前问题存在实质关联才可注入：仅由虚词命中的记忆 MUST NOT 进入注入内容，也 MUST NOT 被记入会话去重集合。

注入的排序 MUST 以关联强度为准，MUST NOT 让最泛的查询词自动获得最高的注入优先级。

#### Scenario: 虚词不算相关

- **WHEN** 用户消息里出现的实义词在库中没有对应记忆，只有虚词能匹配到若干条
- **THEN** 这些记忆不进入注入内容
- **THEN** 面板显示「未命中」，而不是把无关记忆当作召回结果

#### Scenario: 实义词命中优先

- **WHEN** 同一轮里既有短语级命中、又有二字实义词命中
- **THEN** 预算优先给关联更强的命中，被裁掉的是较弱的那些

#### Scenario: 有实义的二字词仍可检索

- **WHEN** 用户消息里含「记忆」「投影」「视频」这类有实义的二字词
- **THEN** 它们照常作为检索词，MUST NOT 被虚词黑名单挡掉

### Requirement: 候选晋升与拒绝的本地命令入口

系统 SHALL 提供本地命令对候选记忆执行晋升或拒绝；命令 SHALL 支持以机器可读形式输出结果并 SHALL 以稳定退出码区分成功、拒绝与故障。晋升命令 SHALL 支持指定作用域，并在结果中报告晋升后的实际作用域。

#### Scenario: 批准一条候选
- **WHEN** 用户执行候选晋升命令并给出候选标识
- **THEN** 系统完成晋升，输出被晋升记忆的标识、状态与权威，并以成功退出码结束

#### Scenario: 批准时指定作用域
- **WHEN** 用户在晋升命令中一并指定作用域预设
- **THEN** 系统按该作用域完成晋升，并在输出中报告实际生效的作用域

#### Scenario: 拒绝一条候选
- **WHEN** 用户执行候选拒绝命令并给出候选标识与理由
- **THEN** 系统将该候选转为墓碑，输出被拒绝记忆的标识与终态，并以成功退出码结束

#### Scenario: 候选标识不存在
- **WHEN** 用户给出的标识在库中不存在
- **THEN** 系统以「未找到」类的稳定退出码结束，输出不包含任何记忆正文

#### Scenario: 对非候选执行拒绝
- **WHEN** 用户试图拒绝一条不是候选的记忆
- **THEN** 系统以状态冲突类的稳定退出码结束并报告当前状态，不改变任何数据

#### Scenario: 命令在无界面环境下运行
- **WHEN** 用户在无可用终端交互的环境下执行这两个命令
- **THEN** 系统以机器可读形式输出结果并以稳定退出码结束，不依赖交互确认

### Requirement: 记忆写入接口暴露重要度

系统 SHALL 在显式写入与候选提交接口上提供可选的重要度参数，并 SHALL 在返回结果中报告实际生效的重要度取值；取值越界时系统 MUST 以校验失败拒绝，MUST NOT 静默截断到边界。

#### Scenario: 写入时指定重要度
- **WHEN** 调用方写入记忆并附带合法的重要度
- **THEN** 系统按该值保存，返回结果包含实际生效的重要度

#### Scenario: 未指定重要度
- **WHEN** 调用方写入记忆未附带重要度
- **THEN** 系统取中间档并在返回结果中如实报告

#### Scenario: 重要度越界
- **WHEN** 调用方传入超出允许范围的重要度
- **THEN** 系统以校验失败拒绝写入，不落库任何内容

#### Scenario: 候选提交时的来源钳制
- **WHEN** 模型以推断来源提交候选并声明超出上限的重要度
- **THEN** 系统保存候选并把重要度钳制到上限，返回结果报告钳制后的实际值

### Requirement: 召回结果按语义区分记录

活动记录 SHALL 区分三种召回结果且 MUST NOT 用同一措辞表达不同的语义：

1. **已注入**：本轮确有 N 条记忆被写入上下文，记录 MUST 报告 N；
2. **已去重**：本轮召回到了候选，但候选全部已在本次会话内注入过，因而本轮未重复注入。该情形 MUST 记录为「已去重」一类，MUST NOT 记为「注入 0」，也 MUST NOT 与「未找到」使用同一措辞；
3. **未命中**：本轮没有召回到任何候选。

当结果为「已去重」时，记录 MUST 同时给出本会话累计注入的条数，使阅读者能把该条与面板左侧的累计列表对应起来。

#### Scenario: 命中但已全部去重

- **GIVEN** 本会话此前已注入过记忆 M，且 M 仍在候选集中
- **WHEN** 下一步自动召回再次命中 M 且无其他新记忆
- **THEN** 活动记录出现一条「已去重」类条目，文字中不出现「注入 0」，并给出本会话累计注入条数

#### Scenario: 真注入与去重不会互相冒充

- **WHEN** 某一步真实注入了 3 条记忆，紧随其后的一步因去重未注入
- **THEN** 两条记录可被肉眼区分：前者报告 3，后者报告已去重，二者措辞不同

#### Scenario: 无候选的诚实表达

- **GIVEN** 本轮所有查询路径都未召回到任何候选
- **WHEN** 记录该步结果
- **THEN** 记录为「未命中」，MUST NOT 标为「已去重」

### Requirement: 空步折叠不淹没真实注入

活动记录 SHALL 把连续的、未产生新注入的同类步骤折叠为一条并记录其发生次数。

折叠 MUST NOT 作用于任何产生了实际注入的步骤：凡携带注入条目的记录 MUST 永远单独成条。

折叠后 MUST 仍可看出该段连续的规模（次数）与其对应的时间范围端点，且 MUST NOT 让真实注入记录因环容量上限而不可见。

#### Scenario: 连续空步被折叠

- **GIVEN** 连续 20 步的自动召回结果都是「已去重」
- **WHEN** 面板读取活动记录
- **THEN** 这 20 步表现为一条带次数的折叠记录，而不是 20 条独立记录

#### Scenario: 真实注入不被折叠

- **GIVEN** 一段连续空步中间夹着一次真实注入
- **WHEN** 活动记录被折叠
- **THEN** 该次真实注入仍然是独立的一条，其注入条目仍可点选高亮

#### Scenario: 折叠不丢时间信息

- **WHEN** 一段连续空步被折叠为一条
- **THEN** 该记录仍带有可读的最后发生时间与次数，用户能判断距上一次真实注入过去了多久

### Requirement: 去重状态随会话上下文重置

系统 SHALL 在本会话上下文被压缩或重置时清空该会话的去重集合与本会话累计注入列表，使此后被重新召回的记忆能够再次注入。

系统 MUST NOT 在其他时机清空它们；会话 id 变化 MUST 视为新会话（新的空状态）。

若宿主未提供可用于判定压缩/重置的信号，系统 MUST 如实降级为「仅在会话 id 变化时重置」，并在用户可见文档中写明该边界，MUST NOT 声称已支持压缩重置。

#### Scenario: 压缩后可以重新注入

- **GIVEN** 某记忆已在本会话注入过并被上下文压缩挤出
- **WHEN** 压缩事件发生后该记忆再次被召回
- **THEN** 系统重新注入该记忆，左栏累计列表按会话重新累计

#### Scenario: 未压缩时不重复注入

- **GIVEN** 本会话未发生压缩
- **WHEN** 同一记忆再次被召回
- **THEN** 系统仍不重复注入（既有去重要求继续生效）

### Requirement: 面板两侧统计口径可自证

面板左侧的「本会话注入的记忆」MUST 展示本会话累计注入的条数，并 MUST 提供一行能解释「左侧按 id 去重累计、右侧记录每一步」的口径说明。

当左侧与右侧数字看起来不一致时（左侧为累计去重条数、右侧为单步条数），该说明 MUST 足以让用户理解这是两个不同的量，而不是数据错误。

#### Scenario: 两个数字并存不引起误读

- **GIVEN** 本会话累计注入 25 条记忆，最近一步因去重未注入
- **WHEN** 用户查看面板
- **THEN** 左栏显示 25 条并附口径说明，右栏该步显示为「已去重」，二者不构成矛盾表述

### Requirement: 同步对账命令入口

系统 SHALL 提供本地命令 `cairn sync backfill`，与该域既有命令 `sync push` / `sync pull` 处于同一命令族；命令 SHALL 支持机器可读输出与稳定退出码，并在未指定应用参数时保持只读。

#### Scenario: 命令出现在帮助与同族命令中

- **WHEN** 用户查看命令行帮助
- **THEN** `sync` 命令族下同时列出 `push`、`pull` 与 `backfill`，且 `backfill` 标注默认只读

#### Scenario: 只读与应用的退出码一致

- **WHEN** 用户分别以只读与应用参数执行对账
- **THEN** 两次都以成功退出码结束，差异只体现在输出报告的写入计数上

#### Scenario: 应用参数错误时拒绝执行

- **WHEN** 用户给出不被支持的对账参数
- **THEN** 系统以用法类稳定退出码结束，且不写入任何待办任务

### Requirement: Agent 拉取与回写批注

系统 SHALL 通过 MCP 提供批注读取与状态回写能力，使 Agent 能在会话内获知"哪些记忆被标注了哪些意见"。

读取 MUST 支持按处置类别、处理状态与条数上限过滤；返回 MUST 只含记忆标识、类别、意见文本与关联状态，MUST NOT 返回记忆完整正文。

回写 MUST 只允许把一条批注标记为已处置或忽略，并 MUST 记录处置者与时间；MUST NOT 通过该接口修改记忆正文或删除记忆。

#### Scenario: 拉取待办批注
- **GIVEN** 用户已在控制台标注若干条记忆
- **WHEN** Agent 调用读取接口
- **THEN** 返回这些批注的类别、意见与记忆标识，且不含记忆正文全文

#### Scenario: 回写处置状态
- **WHEN** Agent 把某条批注标记为已处置
- **THEN** 该批注状态更新并记录处置者与时间，再次读取时不再出现在待办列表

#### Scenario: 回写不改记忆
- **WHEN** Agent 把批注标记为已处置
- **THEN** 对应记忆的正文、状态与修订链不发生任何变化

#### Scenario: 非法状态值
- **WHEN** 回写时给出不被支持的状态值
- **THEN** 系统以参数校验类错误拒绝，不改动任何批注

### Requirement: 压缩后重注入本会话涉及的记忆

宿主报告会话上下文压缩成功后，插件 SHALL 把本次会话中涉及过的记忆重新注入上下文，使其在压缩后仍可见。

"涉及过" SHALL 至少包含：本会话注入过的记忆、以及本会话内经 MCP 被读取或写入过的记忆。

重注入 MUST 遵守既有的注入预算约束；超出预算时 MUST 裁剪并在注入文本中写明省略条数。

重注入文本 MUST 明确标注其来源（压缩前本会话涉及），MUST NOT 与常规召回的注入文本使用同一表述。

#### Scenario: 压缩后重新可见
- **GIVEN** 某记忆在本会话中已被注入过，随后上下文发生压缩
- **WHEN** 压缩成功事件到达
- **THEN** 该记忆的原文重新进入注入文本，且文本中标注为压缩前本会话涉及的内容

#### Scenario: 超出预算时裁剪
- **GIVEN** 本会话涉及过的记忆总量超过注入预算
- **WHEN** 执行重注入
- **THEN** 只注入预算允许的部分，并在文本中写明省略条数，不抛错、不无限膨胀

#### Scenario: 压缩失败不重注入
- **WHEN** 压缩事件带有失败标记
- **THEN** 系统不重注入，且不清空本会话的去重集合

#### Scenario: 重注入后不重复
- **GIVEN** 压缩后已重注入若干记忆
- **WHEN** 下一轮常规召回再次命中其中某条
- **THEN** 该条不再被重复注入

#### Scenario: 会话隔离
- **GIVEN** 会话 A 与会话 B 各自涉及过不同记忆
- **WHEN** 会话 A 发生压缩
- **THEN** 只有会话 A 涉及过的记忆被重注入，B 的不受影响

### Requirement: 会话相关记忆追踪有界

插件 SHALL 在内存中追踪每个会话涉及过的记忆，MUST NOT 写入磁盘，MUST NOT 参与同步。

追踪集合 MUST 有明确上限，超出上限时 MUST 按最近使用淘汰，MUST NOT 无界增长。

#### Scenario: 会话结束即丢弃
- **WHEN** 会话结束或进程退出
- **THEN** 该会话的追踪集合消失，不留下任何磁盘痕迹

#### Scenario: 达到上限时淘汰
- **GIVEN** 某会话涉及过的记忆数达到上限
- **WHEN** 又有新记忆被涉及
- **THEN** 最久未使用的条目被淘汰，集合大小不超过上限

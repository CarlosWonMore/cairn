# @carloswon/cairn-dsh-memory

DeepSeek Harness 的 Cairn 记忆插件：在模型步骤前按当前问题召回记忆并注入。

> **这是体验层，不是内核。** 记忆存储、作用域判定、审批全部由 Cairn MCP server 负责。
> 插件只补 DSH 专属的实时召回。它不拥有数据，也不产生写入。

## 这不是 DSH 专用记忆

市面上有若干名字带 "cairn" / "dsh" 的记忆插件，本插件与它们定位不同：

- **Cairn 是跨 Agent 的记忆主权层**：WorkBuddy / CodeBuddy / Cursor / Copilot / ZCode / DSH 共用一个本地库，换 Agent 不换记忆。
- **本插件只是一个入口**：它通过 MCP 调用 Cairn 内核，不自己存数据。
- **必须先装内核**：`npm i -g @carloswon/cairn-memory` 并接好 MCP，否则召回恒为空。
- 不需要 DSH 时，内核照常可用（CLI / MCP / 其他宿主）。

> 如果你要的是「只给 DSH 用的独立记忆」，本项目不是那个东西——它刻意不做单宿主绑定。

## 为什么需要插件

Cairn 的投影通道（写 `AGENTS.md`）只能**静态注入**：整个会话期间内容不变，且受 2 KB 预算限制。
要按当前问题动态召回，需要挂 `agent/pre-step`——那是 Cordis 插件能力，MCP server（独立进程）做不到。

## 安装

**从 npm 装（推荐）**

```bash
dsh plugin --profile desktop add @carloswon/cairn-dsh-memory
```

**开发态（改源码时）**

```bash
cd plugin/dsh && npm install && npm run build
dsh plugin --profile desktop add <本目录绝对路径>
```

> 无论哪种方式，**先装内核并接好 MCP**：`npm i -g @carloswon/cairn-memory@0.4.0`。
> 重启 DSH 后才生效（插件从 `dist` 加载）。

也可以在 DSH 的插件页手动添加。

## 配置

`cordis.patch.yml` 里可调：

| 项 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `budgetBytes` | `1536` | 单次注入的字节预算 |
| `topK` | `5` | 一次召回最多取几条 |

## 失败时会怎样

插件任何一步失败——MCP 连不上、召回超时、宿主事件参数变化——都**只跳过本次注入**，不把错误抛进会话。

降级后模型仍可通过 `mcp__cairn__*` 工具直接读写记忆。这是 spec 的硬要求：插件故障不能让宿主会话不可用。

## 已验证 / 未验证（诚实边界）

**已由自动化测试覆盖**（`npx tsx --test plugin/dsh/tests/*.test.ts`，94 项）：

- 开关与语义门槛判定（短消息不触发召回）
- 敏感与 `local_only` 命中被过滤，不进入注入
- 预算裁剪：任意预算下输出字节不超限，且写明省略条数
- 同输入同字节（不含时间戳）
- 会话内去重、压缩后重置
- 召回失败时降级不抛错
- 没有召回实现（MCP 未挂）时不注册任何钩子
- **面板渲染结构**（stub React 跑组件树）：不抛错、两栏结构、三态文案、无条目数按钮、空态有文案

**未验证**：

- **与真实 DSH 的集成**：`agent/pre-step` 是否真的被触发、注入文本是否真的进入模型上下文——**未经手工冒烟确认**。
- 与 DSH 版本的兼容矩阵：只在单一桌面端版本上设计，未跨版本验证。

因此能力分级保持 `fixture-only`，不标 `real-cli-tested`。

## 设计取舍

- **不复制检索逻辑**：插件调 Cairn 的检索，自己不写 SQL。否则作用域过滤会有第二份实现——那正是 `promotedPredicate` 曾踩过的坑（6 处各写一份，撤销语义漏了一处）。
- **不改写用户 prompt**：注入是独立的合成消息，会话记录里能分清「用户说的」与「系统塞的」。
- **去重状态放内存**：进程重启只是可能重复注入一次，不值得为此加表。

## 记忆调用面板

会话顶部「对话 / 轨迹」视图旁有一个记忆调用指示器，显示本轮召回情况：

| 字段 | 含义 |
| --- | --- |
| 召回条数 | 本轮命中的候选数 |
| 命中通道 | fts / like / mixed |
| 预算占用 | 已用字节 / 上限 |
| 被过滤 | 因作用域或敏感度被排除的条数 |
| 注入条目 | id / 类型 / 摘要（展开可见） |

**三态用文字标明，不只靠颜色：**

- `已注入` —— 有记忆进入上下文
- `已过滤` —— 命中了但被安全规则排除（**不是「没找到」**）
- `未命中` —— 库里没有相关内容

区分后两者很重要：它们看起来都是「什么都没发生」，但「已过滤」说明安全规则在正常工作，而「未命中」说明记忆库可能没有内容。混为一谈会让人误判成坏了。

**活动记录里的自动召回也按语义分开写，不共用措辞：**

| 记录文字 | 含义 |
| --- | --- |
| `自动召回 候选5 注入3` | 本轮真有 3 条记忆进入上下文 |
| `自动召回 已去重 5 条（本会话已注入 25 条）` | 命中了 5 条候选，但本会话都已注入过——**不是「什么都没找到」** |
| `自动召回 未命中` | 本轮一条候选都没有 |

连续的「未产生新注入」同类步骤会**折叠成一条**：显示 `N 次` 与最近一次时间（`title` 里带首次时间，可算时间跨度）。带注入条目的记录永不折叠——否则空步会把真实注入挤出 120 条的内存环。因此左栏累计条数与右栏单步条数本来就不同，左栏底部有一行口径说明。

面板只显示摘要（最多 60 字符），**永不显示记忆正文**。

### 布局（2026-11-02 起）

分左右两栏，各自滚动：

| 位置 | 内容 |
| --- | --- |
| 左上 | 状态（● 已注入 / 已过滤 / 未命中）+ 召回条数、命中通道、预算占用、被过滤 |
| 左下 | **本会话注入的记忆**（跨轮累计、按 id 去重），空态给文案 |
| 右侧 | **本会话**活动记录：筛选条（自动召回 / 工具调用 / 简要 / 详细 / 文字 / 记录存储）+ 可滚动列表 |

口径说明：左下不再是「本轮」——本轮可能什么都没注入（去重后全被跳过），那时列表会空得让人误会。改成会话累计后，它回答的是「这个会话一共给我注入过哪些记忆」。

**状态与列表都只属于当前会话。** 会话键取 `agent.id`（`Agent.id` 就是 `SessionId`），Client 侧由 slot 的 `inject(sessionId)` 传入；请求带 `?session=<id>`，宿主按会话返回切片。多开会话不再互相串台，去重也是会话级的（A 会话注入过的记忆，B 会话照样会注入）。

**去重的重置时机**：同一会话内已注入的记忆不重复注入，直到上下文被压缩。压缩信号取自宿主的 session 事件 `compaction/end`（在 `app.asar` 的 `KNOWN_SESSION_EVENT_TYPES` 中查证；压缩失败带 `error` 时不重置），触发后清空该会话的去重集合与左下累计。会话 id 变化本身即新会话（空状态）。

**点选联动**：右侧「自动召回」条目可点选，选中后左侧同 id 的记忆条目高亮（背景 + 左侧色条），再点一次取消。工具调用行不可点——它们没有对应的记忆条目。

**已知边界**：重启宿主后「本会话注入的记忆」从空开始。原因见下（落盘不含记忆摘要）。

两栏用 `flex: 1 1 320px` / `1 1 360px` + `flex-wrap` 自适应：窄窗口自动上下堆叠，筛选按钮按组换行。**不提供「显示多少条」的选择**——超出可视高度的记录靠滚动条访问。

**活动记录有自己的滚动条**：宿主在会话进行中会把视图区高度放成自适应（`[data-phase=active] .viewArea{min-height:auto}`），面板根节点的 `height:100%` 因此失效，内部 `overflow:auto` 不会触发——列表会长到撑开整个会话区。所以列表额外带 `maxHeight:56vh` 兜底：容器真给了确定高度时 flex 已经更矮，这个上限不生效。

**栏宽可拖拽**：两栏之间有一条 8px 手柄（鼠标变成左右箭头），拖动即可调整左栏宽度，占比限制在 25%–75%。松手时把占比写进 `localStorage['cairn-memory-tab-layout']`（存占比不存像素，换窗口大小不失真），下次打开自动恢复。右栏底部「重置布局」清掉该值，回到默认的自适应宽度。

实现约束（改布局前先读）：客户端插件只有内联样式，**没有样式表注入通道**，所以自适应只能靠 flex，写不了媒体查询；内部滚动区必须同时有 `flex:1` 与 `min-height:0`，否则 `overflow:auto` 不会触发。

### 落盘只写动作，不写记忆

活动记录落盘（`~/.cairn/activity-dsh.jsonl`）只写时间、类型、动作摘要与会话标识（`s`），**不写 `items`**——摘要是正文的前缀，文件是长期留存面，一旦写进去就收不回来。代价是重启后左下的累计列表从空开始，直到下一次注入。

## 召回精度（2026-11-02 起）

`deriveQueries` 按「出现次数」取二字词，而中文里出现次数最高的二字词几乎全是虚词。实测：`是否` 能 LIKE 出「报告人非本人时不要询问是否关闭」「经验要沉淀到技能」等 4 条互不相干的记忆——它们唯一的共性是含这个虚词。一旦注入，还会被记进会话去重集合，**污染是持久的**。

现在两道闸：

1. **虚词不进查询**：`STOP_TERMS`（一个/这个/可以/是否/我们……约 60 个），`deriveQueries` 从有实义的二字词里取 top2。
2. **按关联强度排序**：强词（汉字 ≥3 或 ASCII 词）2 分、实义二字词 1 分、虚词 0 分，按分降序进预算；同分保持首次命中顺序。

刻意**没有**做「只命中一个二字词就丢弃」：`帮我从记忆库里拉取一下记忆` 这种消息的实义词只有「记忆」，下限会把它误杀。二字词不是天然不可靠，虚词才是。
